> **PURPOSE**: Pre-create A records for Azure Local nodes   
> **MASTER REFERENCE**: [Microsoft Learn - Custom Active Directory configuration (required DNS records)](https://learn.microsoft.com/en-us/azure/azure-local/plan/configure-custom-settings-active-directory?view=azloc-2610#required-dns-records) 

**Status**: Active

## Overview

Pre-create forward lookup A records for each Azure Local node hostname before deployment. Whether you must also create the cluster name object (CNO) and virtual client access name (VCO) records depends on your DNS server, as described next.

### What This Accomplishes

- DNS name resolution for cluster nodes
- Pre-staged DNS records for controlled environments
- Documentation of hostname to IP mappings

### Which DNS records are required

Microsoft Learn 2610 ([Custom Active Directory configuration](https://learn.microsoft.com/en-us/azure/azure-local/plan/configure-custom-settings-active-directory?view=azloc-2610#required-dns-records)) says: if your DNS server doesn't support secure dynamic updates, you must create the required DNS records before you deploy.

| Object | Record type | Required when |
|--------|-------------|---------------|
| Machine name (every machine in the system) | Host A | DNS server does not support secure dynamic updates |
| Cluster CNO | Host A | DNS server does not support secure dynamic updates |
| Cluster VCO (the Cluster-Aware Updating client access point) | Host A | DNS server does not support secure dynamic updates |

Learn notes that Microsoft DNS servers integrated with Active Directory take advantage of secure dynamic updates. This runbook pre-creates the node records for controlled environments either way.

:::info

The active directory information in these documents should have been decided in the [planning phase](../../../planning/) and discovery phases. These are just examples. Please update your scripts with the right OU information, right security groups, DNS, etc.

:::

## DNS Record Creation

Pre-create forward lookup A records for each Azure Local node hostname. Create the cluster name (CNO) and virtual client access name (VCO) records now only if your DNS server does not support secure dynamic updates (see [Non-dynamic DNS](#non-dynamic-dns-cno-and-vco-records) below). With secure dynamic updates available, those records are registered later by the cluster process.

<Tabs groupId="deployment-method">
<TabItem value="manual" label="DNS Manager" default>

1. Open DNS Manager on an authoritative domain DNS server.
2. Expand Forward Lookup Zones → select the Active Directory–integrated zone (for example, `hybrid.mgmt`).
3. For each node:
 - Right‑click the zone → New Host (A or AAAA).
 - Enter node name (for example, `hcinode01`) and its management IPv4 address.
 - Leave "Create associated PTR record" unchecked unless the reverse zone is already delegated and managed.
 - Click Add Host.
4. Repeat for all node hostnames (example: `hcinode01`, `hcinode02`, `hcinode03`, `hcinode04`).
5. Document the mapping (hostname ↔ IP) in the deployment artifacts and store in version control.

#### Code

```powershell
# ============================================================================
# Script: Invoke-DNSNodeRecords.ps1
# Execution: Run FROM management server — reads variables.yml
# Prerequisites: powershell-yaml module, DnsServer RSAT, DNS admin access
# ============================================================================

param(
 [Parameter(Mandatory = $false)]
 [string]$ConfigPath
)

$ScriptDir = Split-Path -Parent $MyInvocation.MyCommand.Path
if ($ConfigPath) {
 $ConfigFile = $ConfigPath
} else {
 $ConfigFile = Join-Path $ScriptDir "..\..\..\..\config\variables.yml"
}
if (!(Test-Path $ConfigFile)) { throw "variables.yml not found at $ConfigFile" }

Import-Module powershell-yaml -ErrorAction Stop
Import-Module DnsServer

$config = ConvertFrom-Yaml (Get-Content -Path $ConfigFile -Raw) -Ordered
$zoneName = $config["active_directory"]["domain"]["fqdn"]

# Build node map from cluster ARM deployment node names and starting IP
# Update variables.yml: active_directory section with node records if defined,
# otherwise populate $nodeMap from your site planning documentation.
$nodeMap = [ordered]@{}
$nodeIds = $config["cluster_arm_deployment"]["arc_node_resource_ids"]
if ($nodeIds) {
 $startIp = [System.Net.IPAddress]::Parse($config["cluster_arm_deployment"]["starting_ip"])
 $bytes = $startIp.GetAddressBytes()
 $offset = 0
 foreach ($id in $nodeIds) {
 $nodeName = ($id -split '/')[-1]
 $bytes[3] = [byte]([int]$bytes[3] + $offset)
 $nodeMap[$nodeName] = ([System.Net.IPAddress]::new($bytes)).ToString()
 $offset++
 }
}

if ($nodeMap.Count -eq 0) {
 Write-Warning "No nodes found in variables.yml — populate cluster_arm_deployment.arc_node_resource_ids or define nodes manually."
 return
}

Write-Host "[1/2] Creating DNS A records in zone: $zoneName" -ForegroundColor Cyan

foreach ($nodeName in $nodeMap.Keys) {
 $ip = $nodeMap[$nodeName]
 if (-not (Get-DnsServerResourceRecord -ZoneName $zoneName -Name $nodeName -RRType A -ErrorAction SilentlyContinue)) {
 Add-DnsServerResourceRecordA -ZoneName $zoneName -Name $nodeName -IPv4Address $ip `
 -AllowUpdateAny -CreatePtr:$false -TimeToLive (New-TimeSpan -Hours 1)
 Write-Host " Created: $nodeName.$zoneName -> $ip" -ForegroundColor Green
 } else {
 Write-Host " Exists: $nodeName.$zoneName" -ForegroundColor Yellow
 }
}

Write-Host "[2/2] Verifying A records..." -ForegroundColor Cyan
Get-DnsServerResourceRecord -ZoneName $zoneName -RRType A |
 Where-Object { $_.HostName -in $nodeMap.Keys } |
 Select-Object HostName, @{n='IPv4';e={$_.RecordData.IPv4Address}}
```

#### Validation

```powershell
$zoneName = $config["active_directory"]["domain"]["fqdn"]
$nodeMap.Keys | ForEach-Object { Resolve-DnsName "$_.$zoneName" -ErrorAction SilentlyContinue | Select-Object Name, IPAddress }
```

## Non-dynamic DNS: CNO and VCO records

Required only if your DNS server does not support secure dynamic updates (Learn 2610). Create a Host A record for the cluster CNO and one for the cluster VCO in addition to the node records. The names and IP addresses come from your deployment plan; the values below are placeholders.

```powershell
#Requires -Version 7.0
Set-StrictMode -Version Latest
$ErrorActionPreference = 'Stop'

$ZoneName    = 'contoso.com'
$ClusterName = 'clus01'       # cluster CNO name from your plan
$ClusterIp   = '10.0.0.20'    # IP address allocated to the CNO in your IP plan
$CauVcoName  = 'clus01-cau'   # Cluster-Aware Updating client access point (VCO) name
$CauVcoIp    = '10.0.0.21'    # IP address allocated to the VCO in your IP plan

foreach ($rec in @(@{ Name = $ClusterName; Ip = $ClusterIp }, @{ Name = $CauVcoName; Ip = $CauVcoIp })) {
    if (-not (Get-DnsServerResourceRecord -ZoneName $ZoneName -Name $rec.Name -RRType A -ErrorAction SilentlyContinue)) {
        Add-DnsServerResourceRecordA -ZoneName $ZoneName -Name $rec.Name -IPv4Address $rec.Ip -CreatePtr:$false
    }
}
```

Learn also notes for environments where secure dynamic updates are not possible that you must create the VCO manually (see [Prestage cluster computer objects in Active Directory Domain Services](https://learn.microsoft.com/en-us/windows-server/failover-clustering/prestage-cluster-adds#more-information)), and that the Windows DNS client dynamic update setting is protected by drift control built into Network ATC. If you disable dynamic update (`Get-NetAdapter "vManagement*" | Set-DnsClient -RegisterThisConnectionsAddress $false`), create the VCO immediately afterwards to avoid the drift rollback. See [Modify security defaults](https://learn.microsoft.com/en-us/azure/azure-local/manage/manage-secure-baseline?view=azloc-2610#modify-security-defaults).

## Disjoint namespace

A disjoint namespace exists when the primary DNS suffix of a domain member does not match the DNS name of its Active Directory domain (for example, a computer named with `corp.contoso.com` that is a member of `na.corp.contoso.com`). Before deploying, per Learn 2610:

1. Append the DNS suffix to the management adapter of every node. The suffix must match the Active Directory domain name.
2. Verify that you can resolve the hostname to the Active Directory FQDN.

```powershell
# Append the DNS suffix (use the management adapter interface index on each node)
Set-DnsClient -InterfaceIndex 12 -ConnectionSpecificSuffix "na.corp.contoso.com"

# Verify resolution
nslookup node1.na.corp.contoso.com
```

You cannot use group policy to configure the DNS suffix list on an Azure Local instance.

## Notes

- Node hostnames are always created in this task. Cluster CNO and VCO records are required now only when the DNS server does not support secure dynamic updates; otherwise they are registered dynamically.
- If secure dynamic updates are available and change control permits, the node-record step can be skipped; retain the section for controlled environments.
- Every machine that becomes part of the Azure Local system requires a DNS record.
- Verify a record with `nslookup <machine name>`.
- Reverse (PTR) records are optional; create only if the reverse zone is already in scope.

## Troubleshooting

### Common Issues

**DNS Record Creation Fails**: Check DNS server permissions and zone access.

**Records Not Resolving**: Verify DNS server configuration and replication.

**Dynamic Updates Blocked**: Create the node, CNO and VCO Host A records manually (see Non-dynamic DNS above).

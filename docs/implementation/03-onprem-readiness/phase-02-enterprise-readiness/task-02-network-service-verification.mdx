## Overview

Verify that customer-provided network services (DNS, NTP) are operational from the management network. These services should already be configured by the customer network team as part of their infrastructure prerequisites.

:::info Pre-Network Infrastructure Validation
This step validates **customer-provided services only** - services that should work before Azure Local Cloud configures switches and firewall rules in Phase 03.

Azure and Dell endpoint connectivity testing occurs in **Phase 03 Step 4** after network infrastructure is configured.
:::

**Performed by:** Engineer on management VLAN workstation

## DNS Resolution Tests

<Tabs groupId="deployment-method">
<TabItem value="manual" label="Manual Verification" default>

1. Open **PowerShell** on the management workstation.
2. Use `Resolve-DnsName` to test each AD domain controller hostname.
3. Use `nslookup` to verify against specific DNS server IPs.
4. Record results (hostname, resolved IP, pass/fail).
5. If any resolution fails, coordinate with the customer DNS team before proceeding.

</TabItem>
<TabItem value="orchestrated" label="Orchestrated Script">

### PowerShell

> **No script in this task folder.** The folder holds only a placeholder. A placeholder prints `NOT IMPLEMENTED`, changes nothing and exits with code 3. The earlier `Set-InfrastructurePrep.ps1` is removed. The OS configuration sets the Windows features and the time source, and the pre-cluster verification checks the node services.

#### Script

| Script | What it does |
|---|---|
| `scripts/deploy/04-cluster-deployment/phase-03-os-configuration/Invoke-AzureLocalOsConfiguration.ps1` | The [OS configuration](../../04-cluster-deployment/phase-03-os-configuration/automated-os-configuration.mdx). It runs `Set-AzureLocalNodeConfiguration.ps1` on each node: it reads each node, changes only what differs from `infrastructure.yml` (for example the `Time` and `Dns` steps), and reports. |
| `scripts/deploy/04-cluster-deployment/phase-05-cluster-deployment/Invoke-AzureLocalPreClusterVerification.ps1` | The [pre-cluster verification](../../../automation/03-automation-guides/arm-validate-deploy.mdx#pre-cluster-verification-gate). Read only. Checks `ND-001` to `ND-012` cover the nodes: WinRM, name, OS build, NTP source, DNS servers, pending restart, processors and memory, boot disk, Windows features, Secure Boot and TPM, and cluster membership. |

#### Run

```powershell
./Invoke-AzureLocalPreClusterVerification.ps1 -InfrastructureFile ./infrastructure.yml -Mode Verify -Category nodes
```

## Validation Checklist

| Service | Test | Expected Result | Status |
|---------|------|-----------------|--------|
| DNS | AD Domain Controllers | Resolved to IPs | ☐ |
| DNS | Planned Node FQDNs | Resolved or warning (optional) | ☐ |
| NTP | Time Source | Configured and responding | ☐ |
| NTP | Time Skew | < 5 minutes | ☐ |
| Ping | OpenGear Console | Reachable | ☐ |
| Ping | Default Gateway | Reachable | ☐ |

---

## Acceptance Criteria

- DNS resolves Active Directory domain controllers
- NTP server responds and time is synchronized (< 5 minute skew)
- OpenGear console server responds to ping
- Default gateway responds to ping
- Results documented for sign-off

:::note Azure Endpoint Testing
Azure and Dell endpoint connectivity testing (management.azure.com, login.microsoftonline.com, dl.dell.com, etc.) will be performed in **Phase 03 Step 4** after network infrastructure is configured.
:::

## Troubleshooting

| Issue | Likely Cause | Resolution |
|-------|--------------|------------|
| DNS resolution fails | Wrong DNS server configured | Verify DNS server IPs from discovery |
| AD DCs don't resolve | DNS not configured for AD zone | Work with customer DNS team |
| NTP not responding | Firewall blocking UDP 123 | Verify NTP server IP and firewall rules |
| OpenGear not reachable | Cabling or IP issue | Check NET1 connection in Step 1 |
| Gateway not reachable | VLAN or routing issue | Verify management VLAN connectivity |

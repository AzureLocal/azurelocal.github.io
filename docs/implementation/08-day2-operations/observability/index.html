Day 2 Observability

DOCUMENT CATEGORY: Implementation Runbook
SCOPE: A deployed and handed-over Azure Local cluster
PURPOSE: Keep the cluster's monitoring working and read it: Insights, the Log Analytics workspace, the Azure Monitor Agent, the data collection rule association, and Sonar
MASTER REFERENCE: Monitor a single Azure Local system with Insights

Status: Active

Scope​

This page covers only what the toolkit sets up for monitoring, and nothing else:

In scopeOut of scope
Azure Local Insights (the Azure Monitor workbook on the cluster resource)Third-party monitoring agents of any kind
The Log Analytics workspace that holds the Insights dataPaid add-on plans and products beyond the workspace's own data charges
The Azure Monitor Agent (AMA) extension on every machinePrometheus, Grafana and other dashboards
The association of the Insights data collection rule (DCR) with every machineWindows Admin Center, OEM hardware monitoring and network device logging (parked)
azurelocal-sonar for deployments and solution updatesWorkload and guest VM monitoring

The workspace, the agent and Insights are set up once, after the deployment, in Part 5, Phase 02: Monitoring and Observability (Tasks 01 to 03). This page is what you do with them afterwards.

What is collected​

Insights uses the Azure Monitor Agent and one data collection rule. Microsoft Learn lists what that rule must hold for the workbook to work:

DataSource
Windows event channelsMicrosoft-Windows-Health/Operational and Microsoft-Windows-SDDC-Management/Operational
Performance countersMemory(*)\Available Bytes, Network Interface(*)\Bytes Total/sec, Processor(_Total)\% Processor Time, RDMA Activity(*)\RDMA Inbound Bytes/sec, RDMA Activity(*)\RDMA Outbound Bytes/sec
DestinationThe Log Analytics workspace named in the rule

Learn recommends the rule Insights creates (its name starts with AzureStackHCI-) over a rule of your own, because it carries a data stream Insights needs. You can add more data to that rule, but every addition is billed (see Cost).

Daily check​

Do these in order. Each check is read only.

#CheckWhereHealthy
1The Insights tileAzure portal: the cluster resource, Capabilities tabConfigured. Needs update means the rule or the workspace changed (see Insights shows Needs update)
2The Health view of the workbookThe cluster resource, InsightsNo open health faults, or only faults you already track. Faults are the Health Service faults, for example PoolCapacityThresholdExceeded
3The Nodes, Virtual machines and Storage viewsThe same workbookEvery node Healthy with a recent Last updated time; volumes Healthy; no unexpected Failed VMs
4The Azure Monitor Agent on every machineEach machine's Extensions page, or the command belowAzureMonitorWindowsAgent with provisioning state Succeeded on every machine
5The rule association on every machineThe command belowEvery machine is associated with the Insights rule
6Data is arrivingThe workspace, Logs, the query belowA heartbeat from every machine in the last 15 minutes

The checks with Azure CLI, from a management machine signed in with read access (values from infrastructure.yml: azure.subscription_id, azure.resource_group, nodes[].arc_machine_name, operations.monitoring.workspace_resource_group, operations.monitoring.data_collection_rule):

#Requires -Version 7.0
Set-StrictMode -Version Latest
$ErrorActionPreference = 'Stop'

# The values come from infrastructure.yml; the names below are examples.
$resourceGroup = 'rg-iic-azl-01'
$machines      = @('iic-azl-n01', 'iic-azl-n02')

foreach ($machine in $machines) {
    # Check 4: the agent extension and its state
    az connectedmachine extension show --resource-group $resourceGroup --machine-name $machine `
        --name AzureMonitorWindowsAgent --query '{name:name, state:provisioningState}' --output table

    # Check 5: the data collection rule associations of the machine
    $machineId = az connectedmachine show --resource-group $resourceGroup --name $machine --query id --output tsv
    az monitor data-collection rule association list --resource $machineId `
        --query '[].{association:name, rule:dataCollectionRuleId}' --output table
}

Check 6, in the workspace (Logs):

Heartbeat
| where TimeGenerated > ago(1h)
| summarize LastHeartbeat = max(TimeGenerated) by Computer, Category
| extend MinutesAgo = datetime_diff('minute', now(), LastHeartbeat)
| order by MinutesAgo desc

Every machine should appear with MinutesAgo under 15. A machine that is missing, or far behind, has an agent or a rule problem (checks 4 and 5) or cannot reach Azure.

To see the health events that feed the workbook:

Event
| where TimeGenerated > ago(24h)
| where EventLog in ('Microsoft-Windows-Health/Operational', 'Microsoft-Windows-SDDC-Management/Operational')
| summarize Events = count() by Computer, EventLog

Repair the setup​

The deployment scripts of Part 5 also serve as the repair. Run them with -WhatIf first: they read infrastructure.yml and change only what differs.

SymptomRun
The workspace or the data collection endpoint is gone or changedTask 01: Configure Log Analytics Workspace
The agent is missing or not Succeeded on a machine (for example after a node was added or repaired)Task 02: Configure Azure Monitor Agent
A machine is not associated with the Insights rule, or the rule lacks a counter or a channelTask 03: Enable HCI Insights

Insights shows Needs update​

Learn names three causes: the data collection rule was changed, a health event channel was removed from it, or one of the five performance counters was removed. Restore the rule (Task 03 stops and says which counter, channel or workspace is wrong), then select Update on the Insights tile.

The workbook is blank​

Right after Insights is enabled, the first data can take up to 15 minutes, and Learn says to allow up to an hour for the agent to gather data. After that, check that the rule holds the event channels and the counters listed above, then run checks 4 to 6. See Troubleshooting guidance for the Azure Monitor Agent.

A node was added or repaired​

A new or repaired machine needs the agent and the rule association like the others. Run Tasks 02 and 03 again after the node joins, then check 4 to 6.

Deployments and updates: Sonar​

Insights shows the cluster's health. It does not follow a deployment or a solution update step by step. For that, use azurelocal-sonar, a local, read-only web page:

  • The stages, one at a time (Start-AzlSonar.ps1 -InfrastructureFile <file> -Monitor <stage>): Discovery (the discovery files and Beacon's results; no Azure sign-in), Provisioning (ZTP), OsConfiguration (the OS configuration event file), Verification (the pre-cluster gate's event file; no Azure sign-in), Validate, Deployment, Update, AddNode and Repair. The default, Auto, follows the whole flow. See Run Sonar.
  • Deployments: the provisioning, Validate and Deploy of a cluster. See Monitor the run with Sonar.
  • Solution updates: Get-AvailableSolutionUpdate.ps1 and Start-AzureLocalSolutionUpdate.ps1 append their run to update-events.jsonl in the events folder (deployment.events_directory, else -ReportDirectory when you pass one, else %ProgramData%\AzureLocalToolkit\<cluster.name>\events). Start-AzlSonar.ps1 -Monitor Update follows that file with no Azure sign-in (it reads the event file only and shows the live Azure poll as not connected). With an Azure sign-in it also shows Azure's own view: while Azure reports an update installing (UpdateInProgress), the update's step tree, times and errors. Sonar read the cluster's update cmdlets on a live 12.2610 cluster after a finished SBE update (a capture was taken on 2026-11-23), but it has not yet followed a whole update live from start to end, so treat the step tree of a running update as unverified. A run that is given -ReportDirectory writes the file there, where Sonar does not look: set deployment.events_directory. See Monitor the toolkit run with Sonar.

Start an update with Task 02: Start the Solution Update and follow it with Sonar or with Task 01: Check for Updates.

Cost​

Insights itself has no separate charge. Learn: you are billed for the amount of data ingested into the Log Analytics workspace and for its retention, with pay-as-you-go pricing and the first 5 GB per billing account per month free. The Insights rule collects only the two event channels and five counters above, so it stays small. Every channel or counter you add to the rule adds to the bill; see the Azure Monitor pricing page for your region.

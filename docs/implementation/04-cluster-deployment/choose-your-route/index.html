Choose Your Route: ISO or Simplified Provisioning

DOCUMENT CATEGORY: Runbook SCOPE: Choosing the OS installation route, and the OS steps each route needs PURPOSE: Know which phases and tasks to run before cluster Validate MASTER REFERENCE: Microsoft Learn — Install the OS and Simplified machine provisioning

Status: Active

Overview​

Every machine has to reach the same state before cluster Validate: the Azure Local OS installed, the OEM's drivers and Solution Builder Extension (SBE) in place, one static management address with one default gateway, the right DNS and time, and an Azure Arc machine with its mandatory extensions. Part 4 gets there by one of two routes:

RouteHow the OS gets thereStatus
ISO or OEM imageYou install from the Microsoft ISO or your OEM's image (Manual OS Installation), configure the OS (Phase 03), then register with Arc (Phase 04)GA
Simplified machine provisioningAzure installs the OS and registers the machine with Arc. You do it in the portal, then Task 06, or end to end with the azurelocal-ztp automationPreview, East US only, no Arc gateway

Simplified provisioning does not do everything Phase 03 does. It leaves Microsoft's inbox network drivers, an empty C:\SBE, DHCP, and a default gateway on more than one adapter. Those still have to be fixed before Validate. The decision matrix below lists each step.

Check Microsoft and your OEM before Validate

OS requirements change between Azure Local releases and between OEM images. Before you run Validate, check Microsoft Learn's OS installation steps and your OEM's deployment guide for your build and hardware, for example Dell's deployment and operations guide. This page is a map, not a replacement for them.

Decision matrix​

Each row is a step that has to be done, or checked, before cluster Validate. Columns:

  • ISO / OEM image: you install from an ISO and follow Phases 02 to 04.
  • Simplified, portal: you provision with Microsoft's simplified machine provisioning in the portal.
  • Simplified, azurelocal-ztp: you run the azurelocal-ztp automation through its Prepare stage.

Legend: You = a step you run · Microsoft = done by the provisioning service · ZTP = done and checked by azurelocal-ztp · Optional · n/a.

On the portal path, Simplified Provisioning Task 06: Prepare Machines for Validate covers the You rows of the OS configuration table.

What "seen on live runs" means

Rows marked that way were read from two Dell AX-760 machines right after simplified provisioning, before any change: inbox drivers, an empty C:\SBE, DHCP on the management adapter, a default gateway on two adapters, DNS from DHCP, and time.windows.com as the time source. Cluster Validate then passed after the azurelocal-ztp Prepare stage, without RDP, ICMP, disabled adapters or a drive wipe.

Known issue: Arc machine names at Deploy​

Simplified provisioning names each Azure Arc machine <device-id>-1, not after the host. On build 12.2690.1003.15, cluster Deploy failed at Deploy Arc infrastructure components with ParentResourceNotFound: that step installs an Arc extension on the Arc machine named after the host, and no such machine exists. Validate passes, because the deployment content that runs this step is only downloaded when Deploy starts, and Validate's Arc checks use the resource IDs you pass in.

Before you deploy on the simplified route, check the troubleshooting page and Microsoft's known issues for your build. The ISO route isn't affected, because the Arc machine carries the host name.

## Overview

Register all cluster nodes with Azure Arc using `Invoke-AzStackHciArcInitialization`. Arc registration is a mandatory prerequisite for Azure Local cloud deployment — without it, the deployment orchestrator cannot communicate with the cluster.

:::info Azure Authentication
Arc registration requires authenticating to **Azure** (not the node OS). Two methods are available:

- **ARM access token** — Pass `-ArmAccessToken` (and `-AccountID`) to `Invoke-AzStackHciArcInitialization`. Microsoft Learn documents this as the non-interactive option; if you omit `-ArmAccessToken`, the script prompts for **device code** authentication. The token can come from a service principal sign-in (`Connect-AzAccount -ServicePrincipal`) or from your own interactive sign-in. Using a service principal to obtain the token is an Azure Local Cloud organisation choice for unattended runs, not a Learn requirement.
- **Device code** — Interactive browser-based login. Learn's default when no token is supplied; also available in the Direct tab through `Connect-AzAccount -DeviceCode`.

Run the script as a **local administrator on every machine** you intend to cluster. The machines must run **release 2505 or later**. Microsoft Learn 2610 also notes that `Invoke-AzStackHciArcInitialization` accepts an optional `TargetSolutionVersion`: the Azure Local solution version used for the initial deployment after registration. If you omit it, the script prompts you to choose from the available versions. Pin it (for 2610 deployments, `12.2610.1004.50`, the 2610 build in the release information) so that every machine gets the same, reproducible version.

Node access (RDP for Direct, WinRM for Orchestrated) is separate — it uses the management server session context or your RDP session. No node credentials are passed to Azure.
:::

:::warning OEM Image Bootstrap
When nodes ship with a preinstalled or outdated Azure Stack HCI OS image (Dell, HPE, Lenovo, etc.), `Invoke-AzStackHciArcInitialization` triggers an automatic OS update cycle:

1. **Scan** — detect current OS version vs. latest baseline
2. **Download** — download update package (~40-60 min depending on network)
3. **Install** — apply the OS update
4. **Reboot** — node reboots to complete the update (WinRM session disconnects)
5. **Resume** — bootstrap service resumes Arc registration using cached SPN token

This is **expected behavior**. The `Invoke-AzStackHciArcInitialization` cmdlet manages the full update + reboot + resume cycle internally. The synchronous `Invoke-Command` session stays alive through reboots — no manual intervention required. Run **Task 03** in a separate window to monitor OEM update progress.

See: [Handle preinstalled or outdated OS images during Azure Arc registration](https://learn.microsoft.com/en-us/azure/azure-local/known-issues?view=azloc-2610)
:::

## Prerequisites

| Requirement | Details |
|---|---|
| Task 01 passed | Connectivity validation succeeded on all nodes |
| Registering identity | The identity whose token is used has `Azure Connected Machine Onboarding` and `Azure Connected Machine Resource Administrator` on the Arc resource group (or is the resource group owner), per Microsoft Learn. If you use a service principal, give it those roles (Contributor alone is not what Learn specifies) |

| Machine release | Azure Local release 2505 or later on every machine |
| Local administrator | The script runs as a local administrator on every machine |
| Node access | RDP/console (Direct) or WinRM from mgmt server (Orchestrated) |

Run on each node individually via RDP or console.

### Option A: Service Principal Authentication (Production)

```powershell
# Task 02 - Register Node with Azure Arc (SPN auth, run on each node)

$TenantId = "REPLACE_TENANT_ID"
$SubscriptionId = "REPLACE_SUBSCRIPTION_ID"
$ResourceGroup = "REPLACE_RESOURCE_GROUP"
$Region = "REPLACE_REGION"
$Cloud = "AzureCloud"
$ArcGatewayId = "REPLACE_ARC_GATEWAY_ID"
$TargetSolutionVersion = "REPLACE_TARGET_SOLUTION_VERSION" # e.g. 12.2610.1004.50 (omit the parameter to be prompted)
$SpnId = "REPLACE_SPN_ID"

if ($TenantId -match '^REPLACE_') { throw 'Edit the REPLACE_ variables before running.' }

# Prompt for SPN secret securely (never hardcode secrets in scripts)
$SpnSecure = Read-Host "Enter SPN secret" -AsSecureString
$SpnSecret = [System.Net.NetworkCredential]::new('', $SpnSecure).Password

# Authenticate with service principal
$SecurePassword = ConvertTo-SecureString $SpnSecret -AsPlainText -Force
$Credential = New-Object System.Management.Automation.PSCredential($SpnId, $SecurePassword)
Connect-AzAccount -ServicePrincipal -TenantId $TenantId -Credential $Credential -SubscriptionId $SubscriptionId

# Get ARM access token
$ArmToken = (Get-AzAccessToken).Token
$AccountId = $SpnId

# Register this node with Arc
Invoke-AzStackHciArcInitialization `
 -SubscriptionID $SubscriptionId `
 -ResourceGroup $ResourceGroup `
 -TenantID $TenantId `
 -Region $Region `
 -Cloud $Cloud `
 -ArmAccessToken $ArmToken `
 -AccountID $AccountId `
 -ArcGatewayID $ArcGatewayId `
 -TargetSolutionVersion $TargetSolutionVersion
```

### PowerShell

> **No script in this task folder.** The folder holds only placeholders (`Invoke-ArcRegistration-Orchestrated.ps1` and the Azure CLI `Register-AzureLocalArc.ps1`). A placeholder prints `NOT IMPLEMENTED`, changes nothing and exits with code 3. The earlier `Register-NodesWithArc.ps1` and `Register-AzureLocalArc-Remote.ps1` are removed. The OS configuration registers a machine that was installed from an ISO in its **ArcRegistration** step. A machine that ZTP provisioned is already registered.

#### Script

| Script | What it does |
|---|---|
| `scripts/deploy/04-cluster-deployment/phase-03-os-configuration/Invoke-AzureLocalOsConfiguration.ps1` | The **ArcRegistration** step looks the Arc machine up in Azure. When it is missing or not Connected, it runs `Invoke-AzStackHciArcInitialization` on the node over WinRM, with an ARM token from the run's own Azure sign-in. |

The step reads `azure.subscription_id`, `azure.resource_group`, `deployment.solution_version` (passed as `TargetSolutionVersion`, so the cmdlet never asks), and the proxy and bypass list of the outbound path (`networking.outbound.proxy` or `networking.outbound.private_path`). When the path needs a value the file does not give, the node is Blocked in the plan. The nodes' local administrator comes from `identity.local_admin` (a secret reference) or `-Credential`. The script never prompts.

#### Run

```powershell
Connect-AzAccount   # the run uses this sign-in for the ARM token

# Plan (the default): which machines would be registered
./Invoke-AzureLocalOsConfiguration.ps1 -InfrastructureFile ./infrastructure.yml -Step ArcRegistration

# Apply
./Invoke-AzureLocalOsConfiguration.ps1 -InfrastructureFile ./infrastructure.yml -Step ArcRegistration -Mode Apply
```

Microsoft provides a GUI wizard — the **Azure Stack HCI Configurator App** — that simplifies Arc registration for smaller or first-time deployments.

| Setting | Value | Source |
|---|---|---|

## Watch the Registration

For OEM image scenarios the nodes can reboot during registration while they install OEM updates. Do not restart the registration script when a node reboots: the bootstrap service resumes by itself.

The toolkit has no monitoring script for this. **Watch the registration and the bootstrap with [Azure Local Sonar](https://azurelocal.cloud/azurelocal-sonar/).** Start it in a second window before you register:

```powershell
Connect-AzAccount
./Start-AzlSonar.ps1 -InfrastructureFile ./infrastructure.yml
```

Sonar reads the nodes and the Azure targets from the same `infrastructure.yml`. It only reads. Task 03 shows the status commands you can run on a node.

## Troubleshooting

| Issue | Resolution |
|---|---|
| SPN auth fails | Verify App ID/Secret and that the identity has `Azure Connected Machine Onboarding` and `Azure Connected Machine Resource Administrator` on the Arc resource group |
| Prompted to choose a solution version | `TargetSolutionVersion` not supplied; pass it (for example `12.2610.1004.50`) for unattended, reproducible runs |
| Token expired mid-run | Re-run `Connect-AzAccount` and get a fresh token |
| WinRM denied (OS configuration) | Confirm WinRM is enabled from Phase 03 and that `identity.local_admin` holds the local administrator. Pass `-Credential` to use another account |
| Arc init timeout | Check node internet connectivity (Task 01) |
| Bootstrap reports InProgress | OEM updates or registration still running — run Task 03 to monitor |
| Bootstrap reports Failed (401) | SPN token expired or session lost — re-run registration with fresh auth |

## Overview

After Arc registration and bootstrap complete, verify that all cluster nodes are properly registered, connected, and ready for Azure Local cluster deployment.

## Prerequisites

| Requirement | Details |
|---|---|
| Arc registration | Completed via Task 02 |
| Bootstrap status | `Succeeded` on all nodes (Task 03) |
| Azure modules | `Az.Accounts`, `Az.ConnectedMachine` |
| Node access | WinRM to all cluster nodes |

## Verification

<TabItem value="direct" label="Direct (per node)" default>

**Run on each cluster node** to verify the local Arc agent:

```powershell
# Check Arc agent service
Get-Service himds | Format-Table Name, Status, StartType

# Show Arc agent registration details
& "$env:ProgramFiles\AzureConnectedMachineAgent\azcmagent.exe" show

# Test endpoint connectivity through Arc Gateway
& "$env:ProgramFiles\AzureConnectedMachineAgent\azcmagent.exe" check
```

<TabItem value="orchestrated" label="Orchestrated Script">

### PowerShell

> **A thin wrapper.** `Invoke-ArcVerification-Orchestrated.ps1` in the task folder keeps the file name of this page and runs the two read only scripts below, one after the other. The earlier `Confirm-ArcRegistration.ps1` and `Confirm-ArcRegistration-Orchestrated.ps1` are removed. The Azure CLI tab has a script that checks the machines in Azure with `az`.

#### Script

| Script | What it does |
|---|---|
| `scripts/deploy/04-cluster-deployment/phase-04-arc-registration/task-04-verify-arc-registration-and-connectivity/powershell/Invoke-ArcVerification-Orchestrated.ps1` | The wrapper, read only. Step 1: `Invoke-AzureLocalOsConfiguration.ps1` in Plan mode with the `ArcRegistration` step. Step 2: `Invoke-AzureLocalArmDeployment.ps1` in Plan mode with that report as `-OsConfigurationReport`; it runs only when step 1 ended with 0. Without `-ReportDirectory` the reports go to a new folder under the temp path of the account, and the progress lines name it. It takes `-InfrastructureFile` (required), `-Node`, `-ReportDirectory`, `-SettingsFile` and `-Credential`. `-WhatIf` prints the command line of each step and runs none. Exit 0: passed or planned. Exit 1: a check failed or a node did not converge. Exit 2: bad input, including a missing file. |
| `scripts/deploy/04-cluster-deployment/phase-03-os-configuration/Invoke-AzureLocalOsConfiguration.ps1` | In Plan mode the **ArcRegistration** step reports, per machine, whether its Arc machine exists and is Connected. It changes nothing. |
| `scripts/deploy/04-cluster-deployment/phase-05-cluster-deployment/Invoke-AzureLocalArmDeployment.ps1` | In `-Mode Plan` it runs the [checks](../../../automation/03-automation-guides/arm-validate-deploy.mdx#what-it-checks-first) before Validate, read only. `ArcMachinesConnected`: each Arc machine exists, is Connected and is in the instance's resource group. `ArcMachineNaming`: each Arc machine is named after the host. |

#### Run

```powershell
./Invoke-ArcVerification-Orchestrated.ps1 -InfrastructureFile ./infrastructure.yml -ReportDirectory ./out

# The two scripts it runs, called directly
./Invoke-AzureLocalOsConfiguration.ps1 -InfrastructureFile ./infrastructure.yml -Step ArcRegistration -ReportDirectory ./osconfig-report

./Invoke-AzureLocalArmDeployment.ps1 -InfrastructureFile ./infrastructure.yml -OsConfigurationReport ./osconfig-report -Mode Plan -ReportDirectory ./arm-plan
```

### Azure CLI

> **When to use**: Check the task from a host that has the Azure CLI and not the Az PowerShell modules. The script is PowerShell 7 that calls `az` and only reads Azure.

#### Script

| Script | What it does |
|---|---|
| `scripts/deploy/04-cluster-deployment/phase-04-arc-registration/task-04-verify-arc-registration-and-connectivity/azurecli/Test-ArcRegistration.azcli.ps1` | Verifies in Azure with the Azure CLI that the Azure Local machines of `nodes[]` are registered with Azure Arc and connected. Read only. Supports `-WhatIf` (lists the checks and runs none). |

Requires: PowerShell 7 and the Azure CLI, signed in with `az login --tenant <azure.tenant_id>`. Needs the Azure CLI extension `connectedmachine` (`az extension add --name connectedmachine`); the script does not install it.

It checks that each machine exists in `azure.resource_group`, that its status is `Connected`, and that the extensions of the Azure Local registration are `Succeeded` (they install some time after the registration, so run it again when one is still `Creating`). `-TargetNode` limits the checks to some nodes. Whether the machines reach the Arc endpoints runs on the machines and is not an Azure CLI task.

#### Run

```powershell
./Test-ArcRegistration.azcli.ps1 -InfrastructureFile ./infrastructure.yml -WhatIf

./Test-ArcRegistration.azcli.ps1 -InfrastructureFile ./infrastructure.yml
```

## Troubleshooting

| Symptom | Resolution |
|---|---|
| `himds` service stopped | `Start-Service himds` — if it fails, check `C:\ProgramData\AzureConnectedMachineAgent\Log\himds.log` |
| `azcmagent show` → Disconnected | Run `azcmagent connect` again or check network/proxy |
| `azcmagent check` fails endpoints | Verify firewall rules allow `*.guestconfiguration.azure.com`, `*.his.arc.azure.com` |
| Node missing from `Get-AzConnectedMachine` | Re-run Task 02 registration for that node |
| Extensions not provisioned | Extensions are deployed during cluster deployment — not required at this stage |

## Azure Portal Verification

For manual confirmation:

1. Navigate to **Azure Arc → Machines** in the [Azure Portal](https://portal.azure.com)
2. Filter by resource group from `infrastructure.yml`
3. Confirm all nodes show **Connected** status
4. Click each node → **Properties** → verify subscription, resource group, and region
5. If using Arc Gateway: **Networking → Gateway configuration** → verify gateway resource ID

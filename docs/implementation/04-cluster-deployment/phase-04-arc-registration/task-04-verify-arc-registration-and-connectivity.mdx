## Overview

After Arc registration and bootstrap complete, verify that all cluster nodes are properly registered, connected, and ready for Azure Local cluster deployment.

## Prerequisites

| Requirement | Details |
|---|---|
| Arc registration | Completed via Task 02 |
| Bootstrap status | `Succeeded` on all nodes (Task 03) |
| Azure modules | `Az.Accounts`, `Az.ConnectedMachine` |
| Node access | WinRM to all cluster nodes |

## Verification

<Tabs groupId="deployment-method">
<TabItem value="direct" label="Direct (per node)" default>

**Run on each cluster node** to verify the local Arc agent:

```powershell
# Check Arc agent service
Get-Service himds | Format-Table Name, Status, StartType

# Show Arc agent registration details
& "$env:ProgramFiles\AzureConnectedMachineAgent\azcmagent.exe" show

# Test endpoint connectivity through Arc Gateway
& "$env:ProgramFiles\AzureConnectedMachineAgent\azcmagent.exe" check
```

</TabItem>
<TabItem value="orchestrated" label="Orchestrated Script">

### PowerShell

> **No script in this task folder.** The folder holds only placeholders (`Invoke-ArcVerification-Orchestrated.ps1` and the Azure CLI `az-verify-arc-registration.ps1`). A placeholder prints `NOT IMPLEMENTED`, changes nothing and exits with code 3. The earlier `Confirm-ArcRegistration.ps1` and `Confirm-ArcRegistration-Orchestrated.ps1` are removed.

#### Script

| Script | What it does |
|---|---|
| `scripts/deploy/04-cluster-deployment/phase-03-os-configuration/Invoke-AzureLocalOsConfiguration.ps1` | In Plan mode the **ArcRegistration** step reports, per machine, whether its Arc machine exists and is Connected. It changes nothing. |
| `scripts/deploy/04-cluster-deployment/phase-05-cluster-deployment/Invoke-AzureLocalArmDeployment.ps1` | In `-Mode Plan` it runs the [checks](../../../automation/03-automation-guides/arm-validate-deploy.mdx#what-it-checks-first) before Validate, read only. `ArcMachinesConnected`: each Arc machine exists, is Connected and is in the instance's resource group. `ArcMachineNaming`: each Arc machine is named after the host. |

#### Run

```powershell
./Invoke-AzureLocalOsConfiguration.ps1 -InfrastructureFile ./infrastructure.yml -Step ArcRegistration

./Invoke-AzureLocalArmDeployment.ps1 -InfrastructureFile ./infrastructure.yml -OsConfigurationReport ./osconfig-report -Mode Plan -ReportDirectory ./arm-plan
```

## Troubleshooting

| Symptom | Resolution |
|---|---|
| `himds` service stopped | `Start-Service himds` — if it fails, check `C:\ProgramData\AzureConnectedMachineAgent\Log\himds.log` |
| `azcmagent show` → Disconnected | Run `azcmagent connect` again or check network/proxy |
| `azcmagent check` fails endpoints | Verify firewall rules allow `*.guestconfiguration.azure.com`, `*.his.arc.azure.com` |
| Node missing from `Get-AzConnectedMachine` | Re-run Task 02 registration for that node |
| Extensions not provisioned | Extensions are deployed during cluster deployment — not required at this stage |

## Azure Portal Verification

For manual confirmation:

1. Navigate to **Azure Arc → Machines** in the [Azure Portal](https://portal.azure.com)
2. Filter by resource group from `infrastructure.yml`
3. Confirm all nodes show **Connected** status
4. Click each node → **Properties** → verify subscription, resource group, and region
5. If using Arc Gateway: **Networking → Gateway configuration** → verify gateway resource ID

:::tip Zero-touch provisioning: we automate this whole route with azurelocal-ztp
**You don't have to do these tasks by hand.** [azurelocal-ztp](https://azurelocal.cloud/azurelocal-ztp/) runs simplified provisioning end to end with no one in the rack and no USB stick:

1. Builds a virtual USB image per machine and boots every machine from it over the BMC (Redfish)
2. Reads each ownership voucher back and claims the machines in Azure with Bicep
3. Waits for Ready to cluster, and resubmits a failed OS install once
4. Verifies each management address, puts back any BIOS value it changed for the install only, and ends at the **Handoff**: Provisioned and Arc-connected

One environment file is the only input. [OS configuration](../phase-03-os-configuration/automated-os-configuration.mdx) (OEM drivers and SBE, static address, one gateway, DNS, time, host name, deployment admin) follows the Handoff. Run it from a Windows management host or a pipeline, and follow it live with [Sonar](./automation/monitor-with-sonar.mdx).

:::warning Handle ownership vouchers like credentials
An ownership voucher (a .pem file named after the machine serial number) is the proof that lets Azure claim a machine. Anyone holding it might try to claim that machine into their own tenant. Store vouchers in a secured, backed-up location until provisioning completes, then delete them. The maintenance environment uses documented default credentials until the target OS is installed, so keep the machines on an isolated network during preparation.
:::

## Overview

Simplified machine provisioning offers an alternative to manual ISO installation. Instead of creating boot media, connecting to each server's management interface, and manually running Windows Setup, this workflow:

1. **Prepares machines** with a USB-based maintenance environment that generates [FIDO Device Onboarding (FDO)](https://fidoalliance.org/device-onboarding-overview/) ownership vouchers
2. **Provisions machines from Azure** — the OS is downloaded and installed automatically, with network configuration and Azure Arc registration handled remotely
3. **Deploys the cluster** using the provisioned machines, just as with ISO-based installation

This approach is most valuable when someone other than on-site staff prepares the machines (e.g., a hardware manufacturer or integrator), and on-site staff simply power them on and connect them to the network.

## ISO vs Simplified Provisioning Comparison

| Aspect | ISO (Manual) | Simplified Provisioning (Preview) |
|--------|-------------|-----------------------------------|
| **Status** | GA — production supported | Preview — East US only |
| **OS Installation** | Manual via iDRAC/BMC virtual console | Automated from Azure |
| **Physical Access** | Required for initial ISO boot | Required for initial USB boot |
| **Network Configuration** | Manual (SConfig or PowerShell) | Automated from Azure portal |
| **Azure Arc Registration** | Separate step (Phase 04) | Included in provisioning flow |
| **Arc Gateway Support** | ✅ Supported | ❌ Not supported (preview) |
| **Supported Hardware** | All Azure Local Catalog hardware | Dell AX-650/750, Lenovo MX650 V3/V4, HPE DL360 Gen11 |
| **Best For** | Production deployments, all hardware | Automated provisioning of supported SKUs |

## Choose your route

This section covers two routes to the same end state: machines with the OS installed and registered with Azure Arc, ready for cluster deployment.

| | Portal route (Tasks 1 to 5) | Automated route (azurelocal-ztp) |
|--|-----------------------------|----------------------------------|
| **How** | You create USB media, boot each machine, collect vouchers, and provision in the Azure portal | One command, or one pipeline, from a Windows management host |
| **Physical access** | Someone attaches USB media and powers on each machine | None after the machines are racked, cabled and reachable by BMC |
| **Needs** | Windows 11 PC, USB drive, the Azure portal | Windows management host with BMC access and an environment file |
| **Ends at** | Ready for Validate after Task 6 (drivers, SBE, static IP, one gateway, DNS, time), or after Phase 03 | The Handoff: Provisioned and Arc-connected. Phase 03 OS configuration (automated or by hand) follows |
| **Support** | Microsoft's documented steps (preview) | Proven on Dell AX-760 / iDRAC 7.30. Not on Learn's validated list for this flow |
| **Start here** | [Task 1: Create USB Installation Media](./task-01-create-usb-media.mdx), through [Task 6](./task-06-prepare-for-validate.mdx) | [Zero-Touch Provisioning Automation](./automation/index.mdx) |

Both routes share the same preview limits: East US only and no Arc gateway. If something goes wrong on either route, see [Troubleshooting and Known Issues](./troubleshooting.mdx).

## Outcome

Upon completion of this section:

- All Azure Local machines have the Azure Stack HCI OS installed, with the host name set by provisioning
- All machines are registered with Azure Arc, with the mandatory extensions
- After [Task 6](./task-06-prepare-for-validate.mdx), or [Phase 03 OS configuration](../../phase-03-os-configuration/index.mdx) after the azurelocal-ztp Handoff: OEM drivers and SBE, one static management address with one gateway, DNS and time
- [Phase 04](../../phase-04-arc-registration/index.mdx) is skipped. Continue with [Phase 05: Cluster Deployment](../../phase-05-cluster-deployment/index.mdx). See the [decision matrix](../../choose-your-route.mdx#decision-matrix)

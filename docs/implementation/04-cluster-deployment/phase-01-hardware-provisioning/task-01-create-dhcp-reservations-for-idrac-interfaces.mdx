## Overview

Create DHCP reservations for iDRAC out-of-band management interfaces using MAC addresses and planned IPs from `infrastructure.yml`. This task is performed **before hardware arrives on site** — MAC addresses come from the Dell order documentation (packing slip or TechDirect), not from a discovery scan.

:::info iDRAC Interfaces Only
This task configures DHCP reservations for **iDRAC (out-of-band) interfaces only**. Management NIC (in-band) reservations are an optional separate task (Task 03). Management NIC static IPs are configured during OS installation.

This task may be skipped if iDRACs have already been assigned static IP addresses prior to deployment.
:::

## Prerequisites

| Requirement | Description | Source |
|-------------|-------------|--------|
| DHCP Server Access | FortiGate admin rights, Windows DHCP admin, or customer DHCP contact | Network team |
| OOB Network Subnet | Out-of-band VLAN and DHCP scope configured | `infrastructure.yml`: `networking.oob.subnet` |
| Node MAC Addresses | iDRAC MAC addresses from Dell order documentation | `infrastructure.yml`: the iDRAC MAC address from the order documentation (it is not a key of `infrastructure.yml`) |
| Planned iDRAC IPs | Assigned iDRAC IP per node | `infrastructure.yml`: `nodes[].bmc.ip_address` |

---

## Values from infrastructure.yml

| Key | What it is |
|-----|------------|
| `networking.oob.subnet` | The out-of-band management network (the DHCP scope) |
| `nodes[].bmc.ip_address` | The planned iDRAC IP address of each node |
| `nodes[].name` | The node host name |
| `nodes[].serial_number` | The Dell service tag |

The iDRAC MAC address and the DHCP server are not keys of `infrastructure.yml`. Take the MAC address from the order documentation or the iDRAC, and ask the network team for the DHCP server.

## Execution Options

Select the tab matching your DHCP infrastructure:

<Tabs groupId="device-type">
<TabItem value="fortigate" label="FortiGate DHCP" default>

> **When to use**: Azure Local Cloud-managed environments using FortiGate firewalls for DHCP

### FortiGate Web UI

1. Open browser to `https://<fortigate-ip>` and log in with admin credentials
2. Navigate to **Policy & Objects** → **DHCP Server**
3. Select the DHCP server for the OOB management network and click **Edit**
4. In the **Reserved Addresses** section, click **Create New** for each node:
 - **IP Address**: `nodes[].bmc.ip_address` from `infrastructure.yml`
 - **MAC Address**: the iDRAC MAC address from the order documentation (it is not a key of `infrastructure.yml`) from `infrastructure.yml`
 - **Description**: `<hostname>-iDRAC (Service Tag: <service-tag>)`
5. Click **OK** to save

### FortiOS CLI (from Management Server)

Connect via SSH from the management server and run the following for each node. Replace values with actual entries from `infrastructure.yml`.

```bash
# ============================================================================
# FortiGate DHCP Reservation — FortiOS CLI
# Execution: SSH FROM management server TO FortiGate
# Prerequisites: SSH access to FortiGate, admin rights
# ============================================================================

ssh admin@<fortigate-ip>

config system dhcp server
 edit "<OOB-DHCP-Server-Name>"
 config reserved-address
 edit "<hostname>-iDRAC"
 set ip <nodes.<name>.idrac_ip>
 set mac <idrac-mac-address>
 set description "iDRAC for <hostname> (ST: <service_tag>)"
 next
 end
 next
end

save config
exit
```

Repeat the `edit` block for each node.

### Validation

```bash
# Verify reservations on FortiGate
show system dhcp server | grep -A5 "iDRAC"
```

### Windows DHCP Console

1. Run `dhcpmgmt.msc` on the DHCP server or an admin workstation with RSAT installed
2. Connect to the DHCP server
3. Expand server → **IPv4** → **Scope [OOB Network]** → **Reservations**
4. Right-click **Reservations** → **New Reservation** for each node:
 - **Reservation name**: `<hostname>-iDRAC`
 - **IP address**: `nodes[].bmc.ip_address` from `infrastructure.yml`
 - **MAC address**: the iDRAC MAC address from the order documentation (it is not a key of `infrastructure.yml`) from `infrastructure.yml`
 - **Description**: `iDRAC for <hostname> (Service Tag: <service-tag>)`
 - Click **Add**

### Information to Provide to Customer

Extract and provide the following from `infrastructure.yml`:

| Field | infrastructure.yml Path | Example |
|-------|------------------------|---------|
| iDRAC MAC address | the iDRAC MAC address from the order documentation (it is not a key of `infrastructure.yml`) | `00:00:5E:00:53:11` |
| Planned iDRAC IP | `nodes[].bmc.ip_address` | `10.100.64.11` |
| Reservation name | Derived: `<hostname>-iDRAC` | `azlocal-node01-iDRAC` |
| Description | Derived | `iDRAC for azlocal-node01 (ST: ABCDE01)` |

1. Extract node data from `infrastructure.yml`
2. Submit request to customer network team with the table above
3. Confirm scope and VLAN with network team
4. Obtain confirmation that reservations have been created
5. Validate (see below)

## Troubleshooting

| Issue | Cause | Resolution |
|-------|-------|------------|
| `DhcpServer module not found` | RSAT not installed | `Install-WindowsFeature RSAT-DHCP` or run directly on DHCP server |
| `Duplicate reservation` | Reservation already exists | Remove existing: `Remove-DhcpServerv4Reservation` then re-add |
| `Scope not found` | Wrong scope ID | Verify: `Get-DhcpServerv4Scope -ComputerName $DHCPServer` |
| `Access denied` | Insufficient rights | Run as DHCP Administrator role member |
| `FortiGate SSH access denied` | SSH not enabled or wrong credentials | Enable SSH on FortiGate admin interface |
| `DHCP server unreachable` | Network connectivity | Verify management server can reach DHCP server |

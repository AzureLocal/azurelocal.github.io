# Task 06 — VM Image Downloads

> **DOCUMENT CATEGORY**: Implementation Guide  
> **SCOPE**: Phase 06 — Post-Deployment | Azure Local  
> **PURPOSE**: Register standard Azure Marketplace VM images on the cluster so they are
> **MASTER REFERENCE**: [Azure Local VM Images](https://learn.microsoft.com/en-us/azure/azure-local/manage/virtual-machine-image-azure-marketplace)
> available for Arc VM deployment

**Status**: Active

[![Phase](https://img.shields.io/badge/Phase-06%20Post--Deployment-blue)](.)
[![Status](https://img.shields.io/badge/Status-Active-green)](.)

**Objective:** Download and register the three standard Azure Marketplace VM images on the
Azure Local cluster. Once registered, images are stored on the cluster's CSV storage and
available for Arc VM provisioning.

:::info Custom images are documented separately
This task covers **Azure Marketplace image downloads only**. Workflows for creating custom
images (sysprep, generalize, upload, or convert from VHDX/VHD) are covered in a dedicated
appendix or in the custom image management section of this documentation.
:::

**Prerequisites:**

- Azure Local cluster deployed and Arc-enabled (Phase 05 complete)
- CSV volumes created and healthy (Task 05 complete)
- Azure identity authenticated: `az login` or Az PowerShell `Connect-AzAccount`
- `az stack-hci-vm` CLI extension installed (`az extension add --name stack-hci-vm`)
- `storage.vm_images[]` populated in `infrastructure.yml`

---

## Values from infrastructure.yml

The script reads these keys from `infrastructure.yml` (schema 5). Each key, with its type, default and example, is in the [variables reference](https://github.com/AzureLocal/azurelocal-toolkit/blob/main/config/variables/docs/VARIABLES.md).

```text
azure.tenant_id, azure.subscription_id, azure.resource_group, azure.location, azure.custom_location, tags, cluster.name (the instance whose Edge Marketplace gives a latest version)
storage.paths[]: name
storage.vm_images[]: name, os_type, publisher, offer, sku, version, storage_path
```

## Download Images

<Tabs groupId="deployment-method">
<TabItem value="manual" label="Azure Portal" default>

**When to use:** Single image creation, visual confirmation of marketplace offer details,
or when CLI access is unavailable.

**Prerequisites:** Access to the Azure Portal with Contributor rights on the resource group.

---

**Steps (repeat for each image):**

1. Navigate to your Azure Local cluster resource: **Azure Portal** → **Azure Local** →
 `iic-clus01`

2. In the left navigation, select **Resources** → **VM images**

3. Click **+ Add VM image** → **Add VM image from Azure Marketplace**

4. Search for the image and select it:

 | Image | Search term |
 |-------|-------------|
 | Windows Server 2025 Datacenter Azure Edition Gen 2 | `Windows Server 2025 Datacenter Azure Edition` |
 | Windows Server 2022 Datacenter Azure Edition Hotpatch Gen 2 | `Windows Server 2022 Datacenter Azure Edition` |
 | Windows 11 Enterprise Multi-Session 25H2 + Microsoft 365 Apps Gen 2 | `Windows 11 Enterprise multi-session` |

 :::note The offer of Windows Server 2022 Azure Edition
 Learn lists every Windows Server image under the offer `windowsserver` ([Create Azure Local VM image using Azure Marketplace images](https://learn.microsoft.com/en-us/azure/azure-local/manage/virtual-machine-image-azure-marketplace?view=azloc-2611)). On the Edge Marketplace of an Azure Local instance, Windows Server 2022 Datacenter: Azure Edition is offered as `windowsserver2022`, so a `storage.vm_images[]` entry for it with `offer: windowsserver` finds nothing. Read the publisher, offer and SKU from the **Image to download** list in the portal before you fill in `storage.vm_images[]`. Windows Server 2025 Datacenter: Azure Edition is `windowsserver`, as Learn says.
 :::

 :::warning Select the correct generation
 Confirm **Gen 2** in the image name before selecting. Gen 1 images are not supported on
 Azure Local Arc VMs and will fail to deploy.
 :::

5. On the **Create VM image** blade, fill in:
 - **Subscription:** `00000000-0000-0000-0000-000000000000`
 - **Resource group:** `rg-iic01-azl-eus-01`
 - **Custom location:** `cl-iic01`
 - **Image name:** e.g. `img-iic01-ws2025-azedition-g2`
 - **Image version:** `latest` (or a specific version)
 - **Storage path:** select a registered storage path (e.g. `sp-iic01-clus01-m2-vmstore-prd-01`)

6. Click **Review + create** → **Create**

7. Image download starts immediately. Progress is visible on the VM images blade. A 40–60 GB image typically takes 15–30 minutes depending on cluster network speed.

8. Repeat for the remaining two images.

### PowerShell

> **When to use**: Run the task from a management workstation or a pipeline. The script reads `infrastructure.yml` and carries no values of its own.

#### Script

| Script | What it does |
|---|---|
| `scripts/deploy/04-cluster-deployment/phase-06-post-deployment/task-06-image-downloads/powershell/New-VmImage.ps1` | Downloads the Azure Marketplace images that storage.vm_images of infrastructure.yml lists to Azure Local, as Azure Local VM images. Supports `-WhatIf`. |

Requires: PowerShell 7, the Az modules Az.Accounts, Az.Resources and Az.StackHCIVM, signed in with `Connect-AzAccount -Tenant <azure.tenant_id>`. It takes `-InfrastructureFile`, `-WhatIf`, `-LogPath`, `-MaxWaitMinutes` and `-PollSeconds`. Exit 0: every image exists (created now, already there, still downloading, planned under `-WhatIf`) or the file lists none. Exit 1: an Azure call or a precondition failed, or an image is `Failed`. Exit 2: a value in the file is missing or not usable (nothing is sent to Azure).

**Waiting for the download.** `New-AzStackHCIVMImage` returns when Azure has accepted the image. While the image is not `Succeeded` the script reads it again every `-PollSeconds` (default 30), prints the state and the percent, and waits up to `-MaxWaitMinutes` (default 60, the time after which this page calls a download stuck; 0 does not wait). An image that an earlier run left downloading gets the same wait. Past the limit the image is reported as `InProgress` (exit 0, not a failure) and the next run reads it again; an image that ends `Failed` is reported with the error Azure gives (exit 1). `-WhatIf` waits for nothing. The images are created one after the other.

**Version.** `latest` is resolved from the Edge Marketplace of the instance (the newest version it offers), not left to Azure, because Azure takes the newest version of the Azure Marketplace, which can be newer than the Edge Marketplace has. The script reports the version it got and never writes it to the file. Pin `storage.vm_images[].version` when you need a fixed version.

**Idempotence.** An image that exists and has `Succeeded` is reported as `AlreadyExists` and left alone. The script reports, without changing anything, when its publisher, offer, SKU, OS type, version or tags differ from the file; a newer Marketplace image is a new image with a new name. The tags are `tags` of the file.

Prerequisite from Learn that the script does not check: the **Azure Connected Machine Resource Manager** role is assigned to the `Microsoft.AzureStackHCI` resource provider app on the resource group ([Learn](https://learn.microsoft.com/en-us/azure/azure-local/manage/virtual-machine-image-azure-marketplace?view=azloc-2611)). The script does check that the `Microsoft.EdgeMarketplace` provider is registered.
#### Run

```powershell
./New-VmImage.ps1 -InfrastructureFile ./infrastructure.yml -WhatIf
./New-VmImage.ps1 -InfrastructureFile ./infrastructure.yml
```

### Azure CLI

> **When to use**: Run the task from a host that has the Azure CLI and not the Az PowerShell modules. The script is PowerShell 7 that calls `az`; it reads `infrastructure.yml` and carries no values of its own.

#### Script

| Script | What it does |
|---|---|
| `scripts/deploy/04-cluster-deployment/phase-06-post-deployment/task-06-image-downloads/azurecli/New-VmImage.azcli.ps1` | Downloads the Azure Marketplace images that storage.vm_images of infrastructure.yml lists to Azure Local, as Azure Local VM images, with the Azure CLI. Supports `-WhatIf`. |

Requires: PowerShell 7 and the Azure CLI, signed in with `az login --tenant <azure.tenant_id>`. Needs the Azure CLI extension `stack-hci-vm` (`az extension add --name stack-hci-vm`); the script does not install it.

Only Azure Marketplace images are supported. The images are created one after the other. The script waits for each download the way the PowerShell tab describes (`-MaxWaitMinutes`, default 60, and `-PollSeconds`, default 30; past the limit the image is `InProgress`, not a failure). `latest` is the newest version of the Edge Marketplace of the instance, and the script reports the version it got without writing it to the file. An image that exists is left alone, and a difference from the file (including the tags) is reported; an image that failed is reported as `Failed` and is not deleted or recreated (delete it with `az stack-hci-vm image delete`, then run the script again). The `Microsoft.EdgeMarketplace` provider must be registered in the subscription (the script checks this).

#### Run

```powershell
./New-VmImage.azcli.ps1 -InfrastructureFile ./infrastructure.yml -WhatIf
./New-VmImage.azcli.ps1 -InfrastructureFile ./infrastructure.yml
```

## Validation

After all images are created, confirm they are in a **Succeeded** provisioning state and
are visible on the cluster's VM images blade.

```powershell title="List all gallery images in the resource group"
az stack-hci-vm image list `
 --subscription 00000000-0000-0000-0000-000000000000 `
 --resource-group rg-iic01-azl-eus-01 `
 --output table
```

```powershell title="Check a specific image status"
az stack-hci-vm image show `
 --subscription 00000000-0000-0000-0000-000000000000 `
 --resource-group rg-iic01-azl-eus-01 `
 --name img-iic01-ws2025-azedition-g2 `
 --query "{Name:name, State:provisioningState, OS:properties.osType}" `
 --output table
```

**Expected results:**

| Name | State | OS |
|------|-------|-----|
| `img-iic01-ws2025-azedition-g2` | Succeeded | Windows |
| `img-iic01-ws2022-azedition-hotpatch-g2` | Succeeded | Windows |
| `img-iic01-win11-25h2-avd-m365-g2` | Succeeded | Windows |

:::warning Image stuck in "Downloading" or "Failed"
If an image stays in `Downloading` for more than 60 minutes or enters `Failed` state:
1. Check cluster storage health — CSV volumes must be online and have sufficient free space
2. Verify the cluster has outbound internet access to `*.blob.core.windows.net` (image source)
3. Delete the failed image and re-run: `az stack-hci-vm image delete --name <img> --resource-group <rg> --yes`
:::

## Troubleshooting

| Issue | Cause | Resolution |
|-------|-------|------------|
| Image stuck in `Downloading` for over 60 minutes | Insufficient CSV free space or blocked outbound connectivity | Check CSV free space: `Get-ClusterSharedVolume`; verify outbound to `*.blob.core.windows.net` on port 443 |
| Image provisioning state is `Failed` | Invalid image source URL or Arc resource bridge issue | Delete and recreate: `az stack-hci-vm image delete --name <img> --resource-group <rg> --yes`; verify bridge health first |
| Image not visible in Azure portal | Sync delay between cluster and Azure | Wait 10-15 minutes; if still missing, verify the custom location resource is healthy: `az customlocation show` |

# Task 09 — Post-Deployment Verification

[![Implementation](https://img.shields.io/badge/Type-Implementation-blue?style=flat-square)](../../index.mdx)

> **DOCUMENT CATEGORY**: Implementation Runbook — Task   
> **SCOPE**: Azure Local cluster — all Phase 06 tasks   
> **PURPOSE**: Confirm all Phase 06 post-deployment configuration tasks completed successfully before proceeding to operational foundations 
> **MASTER REFERENCE**: [Azure Local Deployment Validation](https://learn.microsoft.com/en-us/azure/azure-local/deploy/deployment-introduction)

**Status**: Active

Verify that all Phase 06 tasks completed successfully. This task must pass before the cluster is handed off for operational foundations work.

**Prerequisites:**

- Tasks 01–07 complete
- Administrative access to cluster and management server
- Azure credentials with Reader access to the cluster resource group

#### Task 02 — Cluster Quorum

On a cluster node, run:
```powershell
Get-ClusterQuorum | Format-List Cluster, QuorumResource, QuorumType
```
Confirm a witness is set (`CloudWitness` or `FileShareWitness`). The script on the other tab also checks that the quorum state is `Normal`.

#### Task 03 — Security Groups

On each cluster node, run:
```powershell
Get-LocalGroupMember -Group "Administrators" | Where-Object ObjectClass -eq "Group"
Get-LocalGroupMember -Group "Remote Management Users" | Where-Object ObjectClass -eq "Group"
```
Each should return at least one AD group entry.

#### Task 04 — SSH Connectivity

From the management server:
```powershell
Test-NetConnection -ComputerName iic-01-n01 -Port 22
Test-NetConnection -ComputerName iic-01-n02 -Port 22
```
Expected: `TcpTestSucceeded : True` for all nodes.

#### Task 05 — Storage

**S2D deployments:**

1. On a cluster node, run `Get-ClusterSharedVolume` and `Get-VirtualDisk` — confirm all CSV volumes are **Online** and **Healthy**
2. In Azure Portal → **Azure Local** → `iic-clus01` → **Storage paths** — confirm all show **Succeeded**

**SAN deployments:**

1. Verify FC disk health: `Get-PhysicalDisk | Where-Object BusType -eq 'Fibre Channel'` — all `HealthStatus = Healthy`
2. Verify MPIO paths: `mpclaim -s -d` — ≥2 paths per workload LUN
3. Confirm CSVs are `Online`: `Get-ClusterSharedVolume`
4. In Azure Portal — confirm Azure storage paths show `Succeeded`

#### Task 06 — VM Images

In Azure Portal → **Azure Local** → `iic-clus01` → **VM images** — confirm all required images
show provisioning state **Succeeded**.

#### Task 08 — Logical Networks

In Azure Portal → **Azure Local** → `iic-clus01` → **Logical networks** — confirm all required
logical networks show provisioning state **Succeeded** and VLAN IDs match the site network plan.

### PowerShell

> **When to use**: Verify the deployed instance from a management workstation. The script is read only.

#### Script

| Script | What it does |
|---|---|
| `scripts/deploy/04-cluster-deployment/phase-06-post-deployment/task-09-post-deployment-verification/powershell/Invoke-VerifyPostDeployment.ps1` | Verifies a deployed Azure Local instance against `infrastructure.yml`. Read only. Supports `-WhatIf` (lists the checks and runs none). |

It checks, in this order:

1. **Cluster nodes**: every node of `nodes[]` is a cluster node and its state is Up.
2. **Identity**: with `scenario.identity` `active_directory`, every node is joined to `identity.active_directory.domain_fqdn` and its secure channel works. With `local_identity`, every node is in a workgroup and the cluster name resource has `ADAware` 2.
3. **Quorum**: a quorum type is set and the quorum state is Normal. The deployment creates the witness from `cluster.witness`.
4. **Security groups**: each node has at least one group in Administrators and in Remote Management Users (from `identity.active_directory.security_groups[].local_groups`). Active Directory only.
5. **SSH**: sshd runs on each node and TCP 22 answers.
6. **Storage**: a non-primordial storage pool is healthy, at least one cluster shared volume exists and every one is Online.
7. **VM images in Azure**: the number of images that Succeeded is not below the number in `storage.vm_images[]`.
8. **Logical networks in Azure**: the number that Succeeded is not below the number in `networking.logical_networks[]`.

The login is `-Credential`, else the account the file names: the LCM user (`identity.active_directory.lcm_user`) with Active Directory, the local administrator (`identity.local_admin`) with local identity. The password is a secret reference. The script never prompts: with neither it stops with exit code 2. Exit codes: 0 every check passed; 1 a check failed; 2 a value in the file is missing or there is no login.

`Invoke-PostDeploymentVerification-Orchestrated.ps1` and the Azure CLI `az-verify-post-deployment.ps1` in the task folder are placeholders (exit code 3).

Requires: PowerShell 7; modules FailoverClusters, Storage; the Azure CLI, signed in, for checks 7 and 8.

#### Run

```powershell
./Invoke-VerifyPostDeployment.ps1 -InfrastructureFile ./infrastructure.yml -WhatIf
./Invoke-VerifyPostDeployment.ps1 -InfrastructureFile ./infrastructure.yml
./Invoke-VerifyPostDeployment.ps1 -InfrastructureFile ./infrastructure.yml -TargetNode iic-azl-n01
```

## Phase 06 Completion Criteria

All of the following must be true before proceeding to Phase 17:

- [ ] Cluster quorum configured and state is `Normal`
- [ ] Security groups applied to all cluster nodes (`Administrators` + `Remote Management Users`)
- [ ] SSH running on all cluster nodes, port 22 reachable
- [ ] Storage pool healthy, CSV volumes mounted and online
- [ ] Storage paths registered in Azure with provisioning state `Succeeded`
- [ ] VM images staged with provisioning state `Succeeded`
- [ ] Logical networks created for all workload VLANs, provisioning state `Succeeded`
- [ ] VLAN IDs validated against site network plan
- [ ] Verification script executed with zero failures

## Troubleshooting

| Issue | Cause | Resolution |
|-------|-------|------------|
| Verification script reports failures on storage paths | Storage path registration incomplete or ARB sync pending | Re-run `New-StoragePath.ps1` (it leaves existing paths alone); wait 10 minutes for sync; verify: `az stack-hci-vm storagepath list` |
| VLAN validation fails against network plan | Logical network VLAN IDs don't match site design | Compare `az stack-hci-vm network lnet list` output against site network plan; recreate mismatched logical networks |
| Multiple verification items fail simultaneously | Cluster health issue affecting dependent services | Start with `Get-ClusterNode` and `Get-ClusterGroup` to assess overall cluster health before addressing individual failures |

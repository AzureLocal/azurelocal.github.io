## Overview

Rename each node to its target hostname from `infrastructure.yml`. Nodes must restart to apply the change.

:::warning Computer name rules (Azure Local 2610)
- **Do not use an underscore (`_`)** in the computer name. Learn: "Using an underscore (`_`) in the computer name is not supported, as it impacts storage path creation."
- The computer name is the name shown in the Azure portal and, once joined, in Active Directory. Choose it now; it is not a cosmetic setting.
- Use a name that is unique in the domain and matches the node name in `infrastructure.yml` and the Active Directory preparation (Phase 01).
:::

## Execution Options

<Tabs groupId="deployment-method">
<TabItem value="sconfig" label="SConfig (Recommended)" default>

Run on each node via console, KVM, or RDP. SConfig is the simplest method.

1. At the PowerShell prompt, type `SConfig` and press Enter
2. Select **option 2** — Computer Name
3. Type the hostname from `infrastructure.yml` (`nodes[].name`)
4. Press Enter and confirm
5. Select **Yes** to restart now

Repeat on each node.

</TabItem>

<TabItem value="orchestrated" label="Orchestrated Script">

### PowerShell

> **No script in this task folder.** The folder `scripts/deploy/04-cluster-deployment/phase-03-os-configuration/task-10-configure-hostname` holds only a placeholder. A placeholder prints `NOT IMPLEMENTED`, changes nothing and exits with code 3. The earlier `Set-NodeHostname.ps1` is removed. The OS configuration does this task in its **Hostname** step.

#### Script

| Script | What it does |
|---|---|
| `scripts/deploy/04-cluster-deployment/phase-03-os-configuration/Invoke-AzureLocalOsConfiguration.ps1` | The one entry point of the OS configuration. It runs `Set-AzureLocalNodeConfiguration.ps1` for each node: it reads the node, changes only what differs from `infrastructure.yml`, and reports. `-Step` limits the run to one step. |

The nodes' local administrator comes from `identity.local_admin` of `infrastructure.yml` (the password is a secret reference), or from `-Credential`. The script never prompts. Run settings go in a JSON file given with `-SettingsFile`.

#### Run

```powershell
# Plan (the default): read every node and list what would change
./Invoke-AzureLocalOsConfiguration.ps1 -InfrastructureFile ./infrastructure.yml -Step Hostname

# Apply
./Invoke-AzureLocalOsConfiguration.ps1 -InfrastructureFile ./infrastructure.yml -Step Hostname -Mode Apply
```

See [how the run works](./how-the-run-works.mdx).

## Troubleshooting

| Issue | Resolution |
|---|---|
| Node didn't come back after restart | Wait another 60s then ping the management IP |
| Hostname not applied | Confirm `Rename-Computer` ran without error; restart if needed |
| Hostname contains `_` | Rename the node. An underscore in the computer name impacts storage path creation (Learn). |

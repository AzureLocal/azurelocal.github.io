## Overview

Configure a static IP address on the management network adapter of each Azure Local node. All IP parameters — address, subnet prefix, gateway, and DNS — come from `infrastructure.yml`. The OS configuration does **not** keep the current DHCP-assigned address.

:::warning Explicit values required — verify before running
All IP values in `infrastructure.yml` must be correct before you apply. The run locks in whatever address the file gives.
:::

What the **Network** step of the OS configuration does on each node:
1. Finds the management port by its MAC address. The adapter name is not needed.
2. Reads the current address. When it already matches the file, it changes nothing.
3. Sets the static address, prefix and gateway on that port and turns DHCP off.
4. Applies the change as a guarded change: the node checks it and rolls it back unless the management host confirms it through a new session.
5. Reads the node again at the end of the run and compares it with the file.

## Execution

<Tabs groupId="deployment-method">
<TabItem value="sconfig" label="SConfig Utility" default>

Run on each node via iDRAC Virtual Console or RDP.

:::info Identify the Management Adapter Before Starting
The adapter number shown in SConfig varies. Before selecting, run `Get-NetAdapter` in PowerShell to list all adapters and confirm the correct name. The management adapter name is recorded in `infrastructure.yml`: `nodes[].network_adapters[].name` from the iDRAC discovery performed in Phase 01.

Common adapter names by NIC vendor:

| Vendor | Typical Adapter Name | Notes |
|--------|---------------------|-------|
| Nvidia / Mellanox ConnectX | `Slot 3 Port 1` (or `Slot X Port 1`) | Slot number set during Phase 01 iDRAC discovery |
| Intel (embedded) | `Embedded NIC 1` | Standard on Dell PowerEdge embedded Intel NICs |
| Broadcom (embedded) | `Embedded NIC 1` | Standard on Dell PowerEdge embedded Broadcom NICs |
:::

1. Open iDRAC Virtual Console or connect via RDP
2. Run `Get-NetAdapter` in PowerShell — note the adapter name matching `infrastructure.yml`: `nodes[].network_adapters[].name`
3. Type `SConfig` and press Enter (or it auto-launches)
4. Select option **8** — Network settings
5. SConfig lists adapters by number — select the number corresponding to your management adapter identified in step 2
6. Select option **1** — Set Network Adapter Address
7. Enter **S** for Static
8. Enter the static IP address from `infrastructure.yml`: `nodes[].network_adapters[].ip_address`
9. Enter the subnet mask (e.g., `255.255.255.0` for /24, `255.255.255.128` for /25)
10. Enter the default gateway from `infrastructure.yml`: `networking.management.gateway`
11. Select option **2** — Set DNS Servers; enter primary from `infrastructure.yml`: `networking.management.dns_servers`
12. Enter secondary DNS from `infrastructure.yml`: `networking.management.dns_servers`
13. Repeat for every node

### PowerShell

> **No script in this task folder.** The folder `scripts/deploy/04-cluster-deployment/phase-03-os-configuration/task-03-configure-static-ip-address` holds only a placeholder. A placeholder prints `NOT IMPLEMENTED`, changes nothing and exits with code 3. The earlier `Set-StaticIPAddress.ps1` is removed. The OS configuration does this task in its **Network** step.

#### Script

| Script | What it does |
|---|---|
| `scripts/deploy/04-cluster-deployment/phase-03-os-configuration/Invoke-AzureLocalOsConfiguration.ps1` | The one entry point of the OS configuration. It runs `Set-AzureLocalNodeConfiguration.ps1` for each node: it reads the node, changes only what differs from `infrastructure.yml`, and reports. `-Step` limits the run to one step. |

A change of the management address is a guarded change: the node applies it, checks it and rolls it back unless the management host confirms it through a new session.

The nodes' local administrator comes from `identity.local_admin` of `infrastructure.yml` (the password is a secret reference), or from `-Credential`. The script never prompts. Run settings go in a JSON file given with `-SettingsFile`.

#### Run

```powershell
# Plan (the default): read every node and list what would change
./Invoke-AzureLocalOsConfiguration.ps1 -InfrastructureFile ./infrastructure.yml -Step Network

# Apply
./Invoke-AzureLocalOsConfiguration.ps1 -InfrastructureFile ./infrastructure.yml -Step Network -Mode Apply
```

See [how the run works](./how-the-run-works.mdx).

## Validation Checklist

- [ ] Static IP configured on all nodes
- [ ] `PrefixOrigin` shows `Manual` on each management adapter
- [ ] `DHCP` shows `Disabled` on each management adapter
- [ ] Default gateway reachable from each node
- [ ] DNS servers responding from each node

```powershell
# Run on each node — verify static assignment
$nic = "Embedded NIC 1" # replace with cluster.management_nic_name from infrastructure.yml
Get-NetIPAddress -InterfaceAlias $nic -AddressFamily IPv4 |
 Select-Object IPAddress, PrefixLength, PrefixOrigin

Get-NetIPInterface -InterfaceAlias $nic -AddressFamily IPv4 |
 Select-Object InterfaceAlias, Dhcp

# Test gateway and DNS reachability
Test-Connection -ComputerName (Get-NetRoute -AddressFamily IPv4 | Where-Object { $_.DestinationPrefix -eq "0.0.0.0/0" }).NextHop -Count 1 -Quiet
Resolve-DnsName "azure.microsoft.com" -ErrorAction SilentlyContinue | Select-Object Name, IPAddress
```

## Troubleshooting

| Issue | Cause | Resolution |
|-------|-------|------------|
| The plan shows the node as Blocked | A value the step needs is missing in `infrastructure.yml` | Add the value the message names, then run the plan again |
| `Adapter not found` error | NIC name in config doesn't match the node | Run `Get-NetAdapter` on the node; update `nodes[].network_adapters[].name` in `infrastructure.yml` |
| Node unreachable after the run | The new address cannot be reached from the management host | The node rolls the guarded change back when the management host does not confirm it. Check the address, VLAN and gateway in `infrastructure.yml` and the run report |
| `PrefixOrigin` shows `Dhcp` after script | DHCP not fully disabled | Run `Set-NetIPInterface -InterfaceAlias '<nic>' -Dhcp Disabled` on the node |
| Wrong IP locked in permanently | Incorrect value in `infrastructure.yml` | Correct `nodes[].management.ip_address`, then run the OS configuration again. It finds the difference and changes it |
| Gateway unreachable after config | Wrong gateway in `infrastructure.yml` | Verify `networking.management.gateway`; check upstream switch VLAN |
| DNS not resolving | DNS not set or wrong servers | Verify `networking.management.dns_servers`; run the `Dns` step again |

## Overview

Verify that primary and secondary DNS servers are correctly configured on the management NIC
of every Azure Local node, and that each node can resolve the Azure endpoints required for
Arc registration and Azure Resource Manager communication.

This task does **not** change any configuration — it is a read-only validation step.

:::warning Verify, because DNS can't be changed after deployment
The servers verified here become the permanent DNS servers of the instance. Before you pass this task, confirm they are the same on all nodes, that at least one runs outside the instance, that none is a public resolver such as 8.8.8.8, and that none is in the Azure Resource Bridge ranges (see the list in [Task 05](./task-05-configure-dns-servers.mdx)).
:::

**What the scripts do:**

1. Hard-fail on any `REPLACE` placeholder remaining in `#region CONFIGURATION`
2. Find the management adapter by **exact name** — exit and list adapters if not found
3. Read the configured DNS servers and compare against expected values from `infrastructure.yml`
4. Test resolution of five critical Azure endpoints
5. Report pass/fail per server and per endpoint; exit with code 1 on any failure

## Validation Checklist

- [ ] Primary DNS server matches `infrastructure.yml`: `networking.management.dns_servers`
- [ ] Secondary DNS server matches `infrastructure.yml`: `networking.management.dns_servers`
- [ ] Configuration confirmed on all nodes
- [ ] The same DNS servers on every node, at least one outside the instance, none a public resolver, none in the Azure Resource Bridge ranges
- [ ] `management.azure.com` resolves from all nodes
- [ ] `login.microsoftonline.com` resolves from all nodes
- [ ] `guestnotificationservice.azure.com` resolves from all nodes
- [ ] `dp.kubernetesconfiguration.azure.com` resolves from all nodes

## Troubleshooting

| Issue | Root Cause | Remediation |
|-------|------------|-------------|
| Script hard-fails on startup | `REPLACE` placeholder values remain | Edit `#region CONFIGURATION` with real values from `infrastructure.yml` |
| `Adapter not found` error | NIC name in config doesn't match | Run `Get-NetAdapter` on the node; update `nodes[].network_adapters[].name` in `infrastructure.yml` |
| DNS mismatch — wrong IPs returned | Task 05 not completed or used incorrect values | Re-run Task 05 with correct values from `infrastructure.yml` |
| Azure endpoints fail to resolve | DNS servers unreachable or missing forwarders | Verify DNS servers are online; check forwarder configuration on DNS server |
| Endpoints resolve internally but not externally | DNS forwarder not configured for internet | Add an internet forwarder on the customer DNS server. The forwarder belongs on the DNS server; do not configure a public resolver such as `8.8.8.8` as one of the DNS servers of the nodes (not supported) |
| Orchestrated script: `cluster.management_nic_name not found` | Key missing from `infrastructure.yml` | Add `management_nic_name` to the `cluster:` block in yml |
| Orchestrated script: `dns.primary not found` | Key missing from `infrastructure.yml` | Add `networking.management.dns_servers` to the `dns:` block in yml |
| Node unreachable via PSRemoting | WinRM not configured or firewall blocking | Verify Task 01 (WinRM) completed; check firewall rules |

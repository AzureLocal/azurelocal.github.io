:::info Which storage designs run this task
| Storage design | This task |
|---|---|
| **Disaggregated (SAN only)** | Run it now, on every node, before Arc registration. |
| **Hybrid (Storage Spaces Direct + SAN)** | Not at initial deployment. SAN LUNs are attached after the deployment (2604 or later; FC WWNs are not zoned until then), and the post-deployment verification in Learn's [Connect an external storage array to Azure Local](https://learn.microsoft.com/en-us/azure/azure-local/deploy/enable-external-storage?view=azloc-2610) (steps 7 to 10) applies instead. |
| **Storage Spaces Direct only** | Skip to [Task 15: Complete Combined Script](./task-15-complete-combined-script-all-steps.mdx). |
:::

:::danger Do NOT initialize the infrastructure or performance history LUNs
The infrastructure volume LUN and performance history LUN must remain **RAW** (no partition table, no file system) until the Azure Local deployment wizard runs. Learn: "Don't initialize the drives, as the deployment expects the drive type to be RAW." If you initialize these LUNs before deployment, the deployment can fail.

Workload LUNs are configured **after** cluster deployment — see [Phase 06 Task 05](../phase-06-post-deployment/task-05-storage-configuration.mdx).
:::

## Overview

This task confirms that all required SAN LUNs are correctly presented to all cluster nodes via MPIO, and that the infrastructure LUNs are in the correct RAW state. This is a verification-only step — no disk initialization occurs.

---

## When to Run

| Scenario | Run? |
|----------|------|
| SAN disaggregated deployment, Fibre Channel or iSCSI | ✅ Yes — all nodes |
| Hybrid (S2D + SAN) | ❌ Not at initial deployment — verify after deployment per Learn |
| Storage Spaces Direct (S2D) only | ❌ Skip |
| After FC zoning or LUN masking changes | ✅ Yes — re-verify |

---

## Prerequisites

| Requirement | Details |
|-------------|---------|
| Tasks 12 and 13 complete | HBA drivers (FC) and MPIO (verified, vendor registered and claimed) configured. iSCSI on 2610: connected by the deployment wizard, see the iSCSI note below |
| FC zoning complete (disaggregated only) | The FC fabric administrator has zoned the node HBAs to the array target ports (Learn's rack aware SAN article says "redundant single-initiator zoning according to the fabric and array vendor design"; Learn does not describe single-target zoning, so follow your fabric and array vendor design) so the LUNs are visible **before** Arc registration. For a **hybrid** design, do not zone until after the deployment. |
| SAN LUNs provisioned | Only the two system LUNs are required before deployment: infrastructure (250 GB or larger) and performance history (20 GB or larger), created on the array and unmasked to all nodes with consistent LUN IDs |
| FC fabric connectivity | HBA ports visible in the fabric; zones active |

:::note Coordinate with your SAN administrator
LUN presentation timing must be coordinated with the SAN array administrator. The infrastructure and performance history LUNs are provisioned **before** this step but left uninitialized. Learn: "Workload LUNs are configured after deployment" ([portal deployment, advanced settings](https://learn.microsoft.com/en-us/azure/azure-local/deploy/deploy-via-portal-disaggregated?view=azloc-2610#specify-advanced-settings-and-apply-tags)); presenting them early is optional and only raises the risk that someone initializes them by accident.
:::

:::info iSCSI on Azure Local 2610
On 2610 the deployment wizard's **iSCSI Configuration** connects the targets, so do not enable iSCSI on the machines first (see [Task 12](./task-12-install-fc-hba-drivers-conditional.mdx#iscsi-adapters-disaggregated-iscsi-san)); there is nothing to verify here yet. On 2604 to 2609, after you connect the targets manually, run the same checks below with `BusType` `iSCSI`.
:::

## Required LUN Layout

| LUN | Purpose | Min Size | Expected State |
|-----|---------|----------|----------------|
| Infrastructure Volume | Azure Local system data | 250 GB | RAW — no partition |
| Performance History | Cluster metrics store | 20 GB | RAW — no partition |
| Workload CSVs | VM storage | Per capacity plan | **Configured after deployment** (Learn); optional to present earlier, but never initialize them here |

## Step 1: Rescan and Verify Disks

<Tabs groupId="deployment-method">
<TabItem value="direct" label="Direct (On Node)" default>

Run on each node individually via console, KVM, or RDP.

**Toolkit script:** none for this step. The run does this in its read only **SanVerify** step: each LUN must be seen once, by UniqueId, and `mpclaim -s -d` must list it as an MPIO disk with paths.

```powershell
# Task 14 - Verify SAN LUN Presentation (run on each node)

# Rescan storage subsystem
Update-HostStorageCache

# List all SAN disks (should include the infrastructure and perf-history LUNs)
Get-PhysicalDisk | Where-Object BusType -in 'Fibre Channel','iSCSI' |
    Select-Object FriendlyName, SerialNumber, Size, CanPool, BusType, OperationalStatus |
    Format-Table -AutoSize

# Verify infrastructure LUNs are RAW (no partition table)
Get-Disk | Where-Object {
    $_.BusType -in 'Fibre Channel','iSCSI' -and $_.PartitionStyle -eq 'RAW'
} | Select-Object Number, FriendlyName, Size, PartitionStyle |
    Format-Table -AutoSize

# Confirm MPIO path count per disk
mpclaim -s -d
```

</TabItem>
<TabItem value="orchestrated" label="Orchestrated Script">

Run from the management server against all nodes.

**Toolkit script:** none for this step. The run does this in its read only **SanVerify** step: each LUN must be seen once, by UniqueId, and `mpclaim -s -d` must list it as an MPIO disk with paths.

```powershell
# Task 14 - Verify SAN LUN Presentation (orchestrated, all nodes)
# The management addresses of the nodes: the management port of each entry of nodes[] in infrastructure.yml
$ServerList = @('<node-1-management-ip>', '<node-2-management-ip>')

Write-Host "=== SAN Disk Inventory ===" -ForegroundColor Cyan
Invoke-Command -ComputerName $ServerList -ScriptBlock {
    Update-HostStorageCache
    Get-PhysicalDisk | Where-Object BusType -in 'Fibre Channel','iSCSI' |
        Select-Object @{N='Node';E={$env:COMPUTERNAME}}, FriendlyName, Size, CanPool, OperationalStatus
} | Sort-Object Node | Format-Table -AutoSize

Write-Host "=== RAW Disk Check (Infrastructure LUNs) ===" -ForegroundColor Cyan
Invoke-Command -ComputerName $ServerList -ScriptBlock {
    Get-Disk | Where-Object {
        $_.BusType -in 'Fibre Channel','iSCSI' -and $_.PartitionStyle -eq 'RAW'
    } | Select-Object @{N='Node';E={$env:COMPUTERNAME}}, Number, FriendlyName, Size, PartitionStyle
} | Sort-Object Node | Format-Table -AutoSize
```

</TabItem>

## Expected Results

| Check | Expected |
|-------|---------|
| SAN disks visible on all nodes | ✅ Same LUNs appear on every node (compare `UniqueId`, disk numbers may differ between nodes) |
| Infrastructure LUN (≥250 GB) | `PartitionStyle = RAW` |
| Performance history LUN (≥20 GB) | `PartitionStyle = RAW` |
| MPIO path count | ≥2 paths per LUN (2 HBAs × 1 fabric or 2 × 2 with dual-fabric) |
| `OperationalStatus` | `OK` for all LUNs |

:::warning If LUNs are NOT visible on all nodes
Verify the array host entries and LUN masking (WWPNs for FC, IQNs for iSCSI), and for FC the zoning between each initiator WWPN and the array target ports. Re-run zoning configuration and rescan: `Update-HostStorageCache`. Confirm `mpclaim -s -d` shows paths.
:::

:::warning If a LUN shows multiple entries per node
MPIO is registered but not claiming the disk (lab-verified symptom on a Pure FlashArray: 8 separate disks for 2 LUNs). Verify the `New-MSDSMSupportedHW` hardware IDs match the array vendor, run the `mpclaim -n -i -d` claim from [Task 13](./task-13-configure-mpio-and-vendor-msdsm-conditional.mdx), restart the node and rescan.
:::

---

## Validation Checklist

- [ ] Infrastructure LUN (≥250 GB) visible on all nodes with `PartitionStyle = RAW`
- [ ] Performance history LUN (≥20 GB) visible on all nodes with `PartitionStyle = RAW`
- [ ] No LUN appears more than once per node (MPIO claiming correctly)
- [ ] MPIO path count matches expected value (≥2 per LUN)
- [ ] `OperationalStatus = OK` for all SAN disks
- [ ] No SAN disk was initialized, formatted or added to the cluster

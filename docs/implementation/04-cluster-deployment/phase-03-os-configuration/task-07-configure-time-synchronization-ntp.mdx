## Overview

All Azure Local nodes must synchronize time from the same NTP source before AD domain join and Arc
registration. Kerberos authentication fails when clock skew exceeds five minutes. This task
configures the Windows Time service (`w32tm`) on each node, restarts the service, forces an
immediate resync, and validates the resulting stratum.

**What the scripts do:**

1. Hard-fail on any `REPLACE` placeholder remaining in `#region CONFIGURATION`
2. Configure w32tm with the NTP server from `networking.ntp_servers`
3. Restart the Windows Time service
4. Force an immediate resync (`w32tm /resync /force`)
5. Verify the resulting sync status and stratum — warn if stratum 16 (unsynchronized)

## Configuration Reference

| `infrastructure.yml` path | Script variable | Example |
|----------------------------|----------------|---------|
| `networking.ntp_servers` | `$NTPServer` | `10.100.10.1` |
| `nodes[].network_adapters[].ip_address` | PSRemoting target (orchestrated only) | `10.100.200.11` |
| `nodes[].name` | Node display name (orchestrated only) | `azlocal-node01` |

:::info infrastructure.yml — NTP server list
`networking.ntp_servers` is a YAML list. The direct script uses the primary (first) entry.
The orchestrated script joins all entries as a space-separated `manualpeerlist`, with the `0x8` flag on each peer.
:::

:::info What Microsoft Learn specifies (Azure Local 2610)
From [Install the Azure Local operating system](https://learn.microsoft.com/en-us/azure/azure-local/deploy/deployment-install-os?view=azloc-2610): configure a valid time server on each machine, and validate that the machine is **not using the local CMOS clock** as a time source (`w32tm /query /status`). The command Learn gives is:

```cmd
w32tm /config /manualpeerlist:"ntpserver.contoso.com,0x8" /syncfromflags:manual /update
```

The `0x8` flag tells Windows Time Service to send NTP requests as a client. Learn's command does not include `/reliable:YES`, which would mark every node as a reliable time source, so the scripts below no longer set it. Learn gives the single-peer form only; for several peers the scripts put `,0x8` on each peer in the space-separated list (standard `w32tm` syntax). "Once the machine is domain joined, it synchronizes its time from the PDC emulator." If you domain join the nodes before deployment (supported from 2604; see [Task 03: Manual OS installation](../phase-02-os-installation/manual-installation/task-03-manual-os-installation.mdx#optional-domain-join-before-deployment)), the node follows the domain hierarchy once joined; the manual peer still matters while the node is in a workgroup.
:::

## Execution Options

<Tabs groupId="deployment-method">
<TabItem value="direct" label="Direct Script (On Node)" default>

Run on each node individually — via RDP, console, or KVM.

**Toolkit script**: `scripts/deploy/04-cluster-deployment/phase-03-os-configuration/task-07-configure-time-synchronization-ntp/powershell/Set-NTPConfiguration.ps1`

Set `$NTPServer` to the first entry from `networking.ntp_servers` in `infrastructure.yml`.

```powershell title="Set-NTPConfiguration.ps1"
# -- Edit before running -------------------------------------------------
$NTPServer = "REPLACE_WITH_NTP_SERVER" # networking.ntp_servers
# ------------------------------------------------------------------------

if ($NTPServer -match "^REPLACE_") { Write-Host "[ERROR] Set NTPServer before running" -ForegroundColor Red; exit 1 }

w32tm /config /manualpeerlist:"$NTPServer,0x8" /syncfromflags:manual /update
Restart-Service w32time -Force
w32tm /resync /force
w32tm /query /status

# Learn: the node must not use the local CMOS clock as its source
if ((w32tm /query /status | Out-String) -match 'Local CMOS Clock') { Write-Host "[WARN] Source is still the local CMOS clock" -ForegroundColor Yellow }
```

## Validation Checklist

- [ ] NTP server configured on all nodes (`w32tm /query /config` shows correct peer)
- [ ] Windows Time service running (`Get-Service w32time | Select Status`)
- [ ] Stratum below 16 on all nodes (`w32tm /query /status`)
- [ ] Source is not `Local CMOS Clock` (Learn requirement)
- [ ] Clock skew within 5 minutes on all nodes (Kerberos requirement)

## Troubleshooting

| Issue | Root Cause | Remediation |
|-------|------------|-------------|
| Script hard-fails on startup | `REPLACE` placeholder value remains | Edit `#region CONFIGURATION` with the NTP server from `infrastructure.yml` |
| Stratum 16 after resync | NTP server unreachable or DNS not resolving | Verify NTP server IP; confirm Task 06 (DNS) passed; check firewall rules |
| `w32tm /resync` exits non-zero | Time service not yet fully started | Wait 10 seconds and re-run `w32tm /resync /force` manually |
| Orchestrated: `ntp_servers not found` | Key missing or wrong path in `infrastructure.yml` | Confirm `active_directory.ntp_servers:` list exists in yml |
| Orchestrated: node unreachable | WinRM not enabled or firewall blocking | Verify WinRM configured (Task 01); check firewall allows port 5985/5986 |
| Time keeps drifting back | VM host overriding guest time | Disable Hyper-V Time Synchronization integration service if applicable |

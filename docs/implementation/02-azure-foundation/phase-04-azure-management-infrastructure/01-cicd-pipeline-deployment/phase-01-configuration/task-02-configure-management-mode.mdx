## Objective

Describe the shared management infrastructure in `infrastructure.yml`: the virtual network and its subnets, the VPN gateway, Bastion, the NAT gateway, the network security groups and the optional management VMs. The Terraform code builds them from the file.

---

:::info The Terraform variables come from infrastructure.yml
The Terraform code (`src/terraform`) does not define the facts of an environment a second time. `New-IacVariableFiles.ps1` reads `infrastructure.yml` and writes `terraform.tfvars.json` and `backend.hcl`. The registry says, for every Terraform variable, which key it comes from. Settings that `infrastructure.yml` has no key for yet go in an `extra.tfvars` file (copy `terraform.tfvars.example`). A secret is never written to a file: the generator writes `not-written.txt` and names the environment variable that Terraform reads at run time.
:::

## Configuration

### Network keys

| Key | What it holds |
|-----|---------------|
| `landing_zone.networks[]` | Each virtual network: `name`, `resource_group`, `location`, `address_space`, `dns_servers`, `peer_with` |
| `landing_zone.networks[].subnets[]` | Each subnet: `name`, `prefix`, `network_security_group`, `route_table` |
| `landing_zone.network_security_groups[]` | Each group, with `rules[]` (name, priority, direction, access, protocol, address prefixes, port ranges) |
| `landing_zone.connectivity.vpn_gateway` | `name`, `resource_group`, `network`, `sku`, `bgp_asn`, `site_to_site[]` and `point_to_site` |
| `landing_zone.connectivity.bastion` | `name`, `resource_group`, `sku`, `network` |
| `landing_zone.connectivity.nat_gateway` | `name`, `resource_group`, `network`, `subnets`, `idle_timeout_minutes` |
| `landing_zone.virtual_machines[]` | The optional management VMs (utility server, network device monitor, and so on) |

```yaml
landing_zone:
  networks:
    - name: vnet-iic-mgmt-01
      resource_group: rg-iic-mgmt-01
      location: eastus
      address_space: [192.0.2.0/24]
      subnets:
        - name: GatewaySubnet
          prefix: 192.0.2.0/27
        - name: AzureBastionSubnet
          prefix: 192.0.2.64/26
```

The addresses are documentation addresses. Use your own plan. Write the files with `New-IacVariableFiles.ps1` (see [Task 01](./task-01-configure-core-variables.mdx)).

## VPN Gateway SKU Options

| SKU | Tunnels | Throughput | Zone-Redundant | Use Case |
|-----|---------|------------|----------------|----------|
| VpnGw1 | 30 | 650 Mbps | No | Small deployments |
| VpnGw2 | 30 | 1 Gbps | No | Standard deployments |
| VpnGw3 | 30 | 1.25 Gbps | No | High bandwidth |
| VpnGw1AZ | 30 | 650 Mbps | **Yes** | Small + HA |
| VpnGw2AZ | 30 | 1 Gbps | **Yes** | **Recommended** |
| VpnGw3AZ | 30 | 1.25 Gbps | **Yes** | High bandwidth + HA |

:::tip Recommended SKU
Use `VpnGw2AZ` for zone-redundant high availability with 1 Gbps throughput.
:::

## IP Planning Guidelines

### Subnet Minimums

| Subnet | Minimum | Recommended | Purpose |
|--------|---------|-------------|---------|
| Gateway | /27 (32 IPs) | /27 | VPN Gateway instances |
| Bastion | /26 (64 IPs) | /26 | Azure Bastion service |
| DNS | /28 (16 IPs) | /28 | DNS resolver |
| AZRL | /27 (32 IPs) | /27 or larger | Management VMs |
| Endpoints | /27 (32 IPs) | /27 or larger | Private endpoints |

### Network Conflict Check

Ensure Azure VNet CIDR does not overlap with:
- ✅ On-premises management network
- ✅ On-premises OOB network
- ✅ Cluster networks
- ✅ Other Azure VNets

---

## Validation

- [ ] VNet CIDR does not conflict with on-premises networks
- [ ] All subnets fit within VNet address space
- [ ] Gateway subnet is minimum /27
- [ ] Bastion subnet is minimum /26
- [ ] DNS subnet is minimum /28
- [ ] VPN Gateway SKU supports required bandwidth
- [ ] BGP ASN and IPs are correct
- [ ] Optional server flags set as desired

## Values from infrastructure.yml

The pipeline settings are in the `devops` section of `infrastructure.yml` (schema 5): the platform, the project, the repository, the approval environments, the runners and the Terraform state. The Terraform code does not define these values a second time. `config/variables/scripts/New-IacVariableFiles.ps1` writes `terraform.tfvars.json` and `backend.hcl` from the file. See the [variables reference](https://github.com/AzureLocal/azurelocal-toolkit/blob/main/config/variables/docs/VARIABLES.md).

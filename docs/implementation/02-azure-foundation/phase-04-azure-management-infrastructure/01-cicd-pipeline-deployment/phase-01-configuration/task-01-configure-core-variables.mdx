## Objective

Set the core values that every CI/CD deployment needs (tenant, subscription, location, tags and the CI/CD integration) in `infrastructure.yml`, then write the Terraform variable files from it.

---

:::info The Terraform variables come from infrastructure.yml
The Terraform code (`src/terraform`) does not define the facts of an environment a second time. `New-IacVariableFiles.ps1` reads `infrastructure.yml` and writes `terraform.tfvars.json` and `backend.hcl`. The registry says, for every Terraform variable, which key it comes from. Settings that `infrastructure.yml` has no key for yet go in an `extra.tfvars` file (copy `terraform.tfvars.example`). A secret is never written to a file: the generator writes `not-written.txt` and names the environment variable that Terraform reads at run time.
:::

## Prerequisites

- [ ] `infrastructure.yml` started from a template (see [Variable Management](https://azurelocal.cloud/standards/variables))
- [ ] Azure tenant ID and subscription ID
- [ ] The CI/CD infrastructure of [Part 1](../../../../01-cicd-infra/) deployed: the runners, and the `devops` section of the file filled in

---

## Procedure

### 1. Set the core keys

| Key | What it holds |
|-----|---------------|
| `azure.tenant_id` | The Azure tenant ID |
| `azure.subscription_id` | The target subscription ID |
| `azure.location` | The Azure region |
| `tags` | The resource tags |
| `site.code` | The short site code that the names use |
| `devops` | The CI/CD platform, project, repository, environments, runners and Terraform state |

Every key, with its type, default and example, is in the [variables reference](https://github.com/AzureLocal/azurelocal-toolkit/blob/main/config/variables/docs/VARIABLES.md).

### 2. Check the file

```powershell
./scripts/common/infrastructure/Test-InfrastructureFile.ps1 -Path ./infrastructure.yml
```

### 3. Write the Terraform variable files

```powershell
# Keep the output folder out of the repository.
./config/variables/scripts/New-IacVariableFiles.ps1 -InfrastructureFile ./infrastructure.yml -OutputDirectory D:\work\iac
```

---

## Validation

After you write the files, verify:

- [ ] `Test-InfrastructureFile.ps1` reports no error
- [ ] `terraform.tfvars.json` and `backend.hcl` exist for each environment you use
- [ ] The tenant ID and the subscription ID are the ones of this customer
- [ ] No secret is in a file. The reference in `infrastructure.yml` is the only place a secret is named
- [ ] The output folder is outside the repository

---

## Values from infrastructure.yml

See the table in the procedure above. The older Terraform variables of this page (`customer_name`, `azurelocal_cicd` and `azurelocal_group_object_id`) do not exist in the Terraform code any more.

---

## Troubleshooting

**Issue**: Invalid customer_name format 
**Solution**: Customer name must be lowercase with hyphens only (e.g., `acme`, `global-tech`)

**Issue**: Invalid environment value 
**Solution**: Environment must be 3 characters or less: `prd`, `dev`, `stg`, `qa`, etc.

**Issue**: Azure region not available 
**Solution**: Verify region name with `az account list-locations -o table`

**Issue**: Cannot find runner principal ID 
**Solution**: Check Part 1 CI/CD Infrastructure deployment outputs or CI/CD pipeline variables

## Objective

Describe the cluster side of the environment in `infrastructure.yml`: the on-premises VPN peer, the cluster Key Vault and witness, and the nodes. The Terraform code builds the Azure foundation only. The cluster itself is deployed with the ARM template in [Phase 05](../../../../04-cluster-deployment/phase-05-cluster-deployment/index.mdx).

---

:::info The Terraform variables come from infrastructure.yml
The Terraform code (`src/terraform`) does not define the facts of an environment a second time. `New-IacVariableFiles.ps1` reads `infrastructure.yml` and writes `terraform.tfvars.json` and `backend.hcl`. The registry says, for every Terraform variable, which key it comes from. Settings that `infrastructure.yml` has no key for yet go in an `extra.tfvars` file (copy `terraform.tfvars.example`). A secret is never written to a file: the generator writes `not-written.txt` and names the environment variable that Terraform reads at run time.
:::

## Configuration

| Key | What it holds |
|-----|---------------|
| `landing_zone.connectivity.vpn_gateway.site_to_site[]` | The on-premises peer: `connection_name`, `local_gateway_name`, `peer_public_ip`, `peer_address_prefixes`, `peer_bgp_address`, `peer_asn`, `shared_key` (a secret reference) |
| `cluster.name`, `cluster.deployment_mode` | The cluster name and deployment mode |
| `cluster.key_vault` | The cluster Key Vault: `name`, `create_new`, `soft_delete_retention_days` |
| `cluster.witness` | The witness: `type`, `storage_account`, `path` |
| `nodes[]` | Each machine: `name`, `serial_number`, `bmc`, `network_adapters[]` |
| `networking.outbound.arc_gateway` | The Azure Arc gateway: `name` and `resource_group` |

Every key, with its type, default and example, is in the [variables reference](https://github.com/AzureLocal/azurelocal-toolkit/blob/main/config/variables/docs/VARIABLES.md).

### Node names

Pick a node naming pattern and keep it. Names follow the pattern `{cluster}-{node}-{env}-{location}`, for example `iic-clus01-n01`.

## Resources Deployed

When cluster mode is configured, these resources are created:

| Resource | Purpose |
|----------|---------|
| VPN Connection | Site-to-site connectivity to cluster network |
| Key Vault | Cluster-specific secrets storage |
| Log Analytics Workspace | Cluster monitoring and logs |
| Storage Account | Cloud witness for cluster quorum |
| DNS A Records | Name resolution for all cluster nodes |
| Arc Gateway (optional) | Hybrid cloud management |

## Values from infrastructure.yml

The pipeline settings are in the `devops` section of `infrastructure.yml` (schema 5): the platform, the project, the repository, the approval environments, the runners and the Terraform state. The Terraform code does not define these values a second time. `config/variables/scripts/New-IacVariableFiles.ps1` writes `terraform.tfvars.json` and `backend.hcl` from the file. See the [variables reference](https://github.com/AzureLocal/azurelocal-toolkit/blob/main/config/variables/docs/VARIABLES.md).

## Troubleshooting

| Issue | Cause | Resolution |
|-------|-------|------------|
| Cluster mode configuration errors | Invalid cluster topology settings | Verify cluster mode variables match deployment topology |
| Mode validation fails | Dependencies between management and cluster modes not met | Configure management mode before cluster mode |

## Overview

This task creates the management Key Vault used to store deployment secrets (VPN shared keys, domain admin passwords, service account credentials) and certificates. All scripts that reference `keyvault://` URIs in `infrastructure.yml` resolve secrets from this vault.

:::info Task Classification
**Execution Target**: Azure-Only (control-plane API operation) 
**Tab Profile**: 2 tabs — Azure Portal · Azure CLI / PowerShell
:::

:::info Terraform Reference
**Module:** `azurelocal-toolkit` 
**File:** `key-vault.tf` 
**Mode:** Management
:::

### Components Created

| Resource | Name Pattern | Purpose |
|----------|-------------|---------|
| Key Vault | `kv-{customer}-platform` | Management secrets store |

### Key Vault Configuration

| Setting | Value | Source |
|---------|-------|--------|
| Name | Per config | `key_vaults[].name` |
| SKU | Standard | Default |
| Soft Delete | 7 days retention | Security best practice |
| Purge Protection | Enabled | Production requirement |
| RBAC Authorization | Enabled | Preferred over access policies |
| Public Access | Enabled | Required for Azure Local today |
| Network ACLs | Bypass Azure Services | `AzureServices` bypass |

### Secrets to Populate

| Secret Name | Purpose | Config Path |
|-------------|---------|-------------|
| `azlocal-admin-password` | Azure Local node admin | a `keyvault://` reference in the key that needs the secret |
| `recovery-admin-password` | Recovery admin | a `keyvault://` reference in the key that needs the secret |
| `vpn-shared-key` | S2S VPN PSK | a `keyvault://` reference in the key that needs the secret |

## Prerequisites

- [ ] Resource group exists
- [ ] Key Vault Administrator or Contributor role
- [ ] Secrets values prepared (do NOT store in YAML — use Key Vault only)

## Values from infrastructure.yml

The script reads these keys from `infrastructure.yml` (schema 5). Each key, with its type, default and example, is in the [variables reference](https://github.com/AzureLocal/azurelocal-toolkit/blob/main/config/variables/docs/VARIABLES.md).

```text
azure.tenant_id, azure.location, tags, scenario.environment_class
key_vaults[].name, .subscription_id, .resource_group, .purpose
every keyvault://<vault>/<secret> reference anywhere in the file (names only; no value is read)
```

1. **Create Key Vault**:
 - Search for **Key vaults** → **+ Create**
 | Field | Value | Source |
 |-------|-------|--------|
 | Name | Per config | `key_vaults[].name` |
 | Subscription | Target subscription | `landing_zone.subscriptions[].id` |
 | Resource Group | Management RG | `key_vaults[].resource_group` |
 | Region | Your region | `azure.location` |
 | Pricing tier | Standard | — |

2. **Access Configuration**:
 | Field | Value |
 |-------|-------|
 | Permission model | Azure role-based access control (recommended) |
 | Resource access | Enable Azure Resource Manager for template deployment |
 | Resource access | Enable Azure Virtual Machines for deployment |

3. **Networking**:
 | Field | Value |
 |-------|-------|
 | Public access | All networks (required for Azure Local today) |
 | Allow trusted Microsoft services | Yes |

4. **Review + create**: Verify → Click **Create**

5. **Add Secrets**: For each secret in the table above:
 - Key Vault → **Secrets** → **+ Generate/Import**
 - Set **Name** and **Value** for each secret

## Troubleshooting

| Issue | Root Cause | Remediation |
|-------|-----------|-------------|
| Name already taken | Key Vault names globally unique | Choose different name or recover soft-deleted vault |
| Soft-deleted vault blocks creation | Same name in deleted state | Purge: `Remove-AzKeyVault -VaultName $name -InRemovedState -Location $location` |
| Cannot access secrets | Missing RBAC role | Assign `Key Vault Secrets User` or `Key Vault Administrator` |
| Network access denied | Firewall blocking | Add client IP to network ACLs or use Azure Services bypass |
| Purge protection cannot be disabled | By design — irreversible | Plan purge protection before creation |

## Overview

This task deploys Azure Bastion into the AzureBastionSubnet created in Task 01. Bastion provides secure, browser-based RDP and SSH access to management VMs without requiring public IP addresses on target resources.

:::info Task Classification
**Execution Target**: Azure-Only (control-plane API operation) 
**Tab Profile**: 2 tabs — Azure Portal · Azure CLI / PowerShell
:::

:::info Terraform Reference
**Module:** `azurelocal-toolkit` 
**File:** `bastion.tf` 
**Mode:** Management
:::

### Components Created

| Resource | Name Pattern | Purpose |
|----------|-------------|---------|
| Public IP | `pip-bastion-{env}-{region}-01` | Bastion public IP |
| Azure Bastion | `bas-azrl-{env}-{region}-01` | Secure RDP/SSH proxy |

### Bastion Configuration

| Setting | Value | Source |
|---------|-------|--------|
| SKU | Standard | `landing_zone.connectivity.bastion.sku` |
| Subnet | AzureBastionSubnet | `landing_zone.networks[].subnets[].name` |
| Features | File transfer, shareable links | Standard SKU features |

## Prerequisites

- [ ] [Task 01: Virtual Network](./task-01-virtual-network) completed — AzureBastionSubnet exists with /26 or larger
- [ ] [Task 06: NSG](./task-06-network-security-groups) — Bastion NSG applied (can be done concurrently)
- [ ] No existing Bastion deployment in same VNet

## Values from infrastructure.yml

The script reads these keys from `infrastructure.yml` (schema 5). Each key, with its type, default and example, is in the [variables reference](https://github.com/AzureLocal/azurelocal-toolkit/blob/main/config/variables/docs/VARIABLES.md).

```text
azure.tenant_id, azure.location, tags
landing_zone.connectivity.bastion.name, .resource_group, .sku, .network     the host, its group, its SKU and its virtual network
landing_zone.networks[].name, .subscription, .resource_group, .location    where the network is
landing_zone.subscriptions[].name, .id                                     the subscription that holds the network
```

<Tabs groupId="deployment-method">

### Azure Portal

> **When to use**: Learning Azure Local, single deployment, prefer visual interface

#### Procedure

1. **Create Public IP**:
 - Search for **Public IP addresses** → **+ Create**
 | Field | Value | Source |
 |-------|-------|--------|
 | Name | `pip-bastion-{env}-{region}-01` | no key (the script or Azure decides it) |
 | SKU | Standard | Required for Bastion |
 | Assignment | Static | Required for Bastion |
 | Availability Zone | Zone-redundant | Best practice |

2. **Create Azure Bastion**:
 - Search for **Bastions** → **+ Create**
 | Field | Value | Source |
 |-------|-------|--------|
 | Name | `bas-azrl-{env}-{region}-01` | `landing_zone.connectivity.bastion.name` |
 | Region | Your region | `azure.location` |
 | Tier | Standard | `landing_zone.connectivity.bastion.sku` |
 | Virtual network | Management VNet | `landing_zone.networks[].name` |
 | Subnet | AzureBastionSubnet (auto-selected) | `landing_zone.networks[].subnets[].name` |
 | Public IP | Select PIP from Step 1 | no key (the script or Azure decides it) |

3. **Review + create**: Verify → Click **Create** → Wait for deployment (~5 minutes)

#### Validation

- [ ] Bastion provisioning state: **Succeeded**
- [ ] Public IP assigned
- [ ] Can connect to VM via Bastion from Azure Portal

## Troubleshooting

| Issue | Root Cause | Remediation |
|-------|-----------|-------------|
| Bastion deployment fails | AzureBastionSubnet too small | Ensure /26 or larger |
| Cannot connect to VM | NSG blocking Bastion traffic | Apply Bastion NSG rules (Task 06) |
| Bastion DNS not resolving | Propagation delay | Wait 5 minutes and retry |
| File transfer unavailable | Basic SKU deployed | Upgrade to Standard SKU |
| Session disconnects frequently | Network instability | Check Bastion subnet NSG rules |

> **MASTER REFERENCE**: [Microsoft Learn - NAT Gateway](https://learn.microsoft.com/en-us/azure/nat-gateway/nat-overview)

**Status**: Active

## Overview

This task deploys an Azure NAT Gateway and associates it with the management subnet. The NAT Gateway provides deterministic outbound internet connectivity with a static public IP, eliminating SNAT port exhaustion and ensuring consistent outbound IP for allowlisting.

:::info Task Classification
**Execution Target**: Azure-Only (control-plane API operation) 
**Tab Profile**: 2 tabs — Azure Portal · Azure CLI / PowerShell
:::

:::info Terraform Reference
**Module:** `azurelocal-toolkit` 
**File:** `nat-gateway.tf` 
**Mode:** Management
:::

### Components Created

| Resource | Name Pattern | Purpose |
|----------|-------------|---------|
| Public IP | `pip-azrlnat-{env}-{region}-01` | NAT Gateway public IP |
| NAT Gateway | `ng-azrl-{env}-{region}-01` | Outbound internet access |
| PIP Association | — | Link PIP to NAT GW |
| Subnet Association | — | Link NAT GW to management subnet |

### NAT Gateway Configuration

| Setting | Value | Source |
|---------|-------|--------|
| SKU | Standard | Default |
| Idle Timeout | Per config (minutes) | `landing_zone.connectivity.nat_gateway.idle_timeout_minutes` |
| Subnet | Management subnet | `landing_zone.networks[].subnets[].name` |

## Prerequisites

- [ ] [Task 01: Virtual Network](./task-01-virtual-network) completed — Management subnet exists
- [ ] Public IP not already consumed

The script reads these keys from `infrastructure.yml` (schema 5). Each key, with its type, default and example, is in the [variables reference](https://github.com/AzureLocal/azurelocal-toolkit/blob/main/config/variables/docs/VARIABLES.md).

```text

landing_zone.connectivity.nat_gateway.name, .resource_group, .network, .subnets, .idle_timeout_minutes
landing_zone.networks[].name, .subscription, .resource_group, .location     where the network is
landing_zone.subscriptions[].name, .id                                      the subscription that holds the network
```

### Azure Portal

> **When to use**: Learning Azure Local, single deployment, prefer visual interface

#### Procedure

1. **Create Public IP**:
 - Search for **Public IP addresses** → **+ Create**
 | Field | Value |
 |-------|-------|
 | Name | `pip-azrlnat-{env}-{region}-01` |
 | SKU | Standard |
 | Assignment | Static |

2. **Create NAT Gateway**:
 - Search for **NAT gateways** → **+ Create**
 | Field | Value | Source |
 |-------|-------|--------|
 | Name | `ng-azrl-{env}-{region}-01` | Naming convention |
 | Region | Your region | `azure.location` |
 | Availability zone | No zone | Or zone-redundant |
 | Idle timeout | Per config (minutes) | `landing_zone.connectivity.nat_gateway.idle_timeout_minutes` |

3. **Outbound IP**: Select the Public IP created in Step 1

4. **Subnet**: Select the management subnet from the VNet

5. **Review + create**: Verify → Click **Create**

- [ ] Public IP associated

- [ ] Outbound connectivity works from management VMs

## Troubleshooting

| Issue | Root Cause | Remediation |
|-------|-----------|-------------|
| SNAT port exhaustion | Too many concurrent connections | Add additional public IPs to NAT GW |
| NAT GW not taking effect | Subnet not associated | Verify subnet association |
| Conflicts with load balancer | LB outbound rules take precedence | Remove LB outbound rules or use NAT GW only |
| Idle timeout too short | Connections drop prematurely | Increase idle timeout (max 120 min) |

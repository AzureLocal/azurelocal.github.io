# Part 7: Validation & Handover

[![Implementation](https://img.shields.io/badge/Type-Implementation-blue?style=flat-square)](../index.mdx)
[![Azure](https://img.shields.io/badge/Platform-Azure_Local-0078D4?style=flat-square&logo=microsoftazure)](https://learn.microsoft.com/en-us/azure/azure-local/)

> **DOCUMENT CATEGORY**: Implementation Runbook   
> **SCOPE**: A deployed Azure Local cluster, after the tests of [Part 6](../06-testing-validation/index.mdx)   
> **PURPOSE**: Collect the evidence that the cluster is healthy, write the documentation package and transfer access to the customer   
> **MASTER REFERENCE**: [Azure Local deployment validation](https://learn.microsoft.com/en-us/azure/azure-local/deploy/validate)

**Status**: Active

Part 6 is the acceptance test of the cluster (health, storage performance with VMFleet, RDMA, failover, security). Part 7 is the evidence run that goes with the handover: four read-only checks that read the cluster name from `infrastructure.yml` and can be run again at any time (they are also the checks to repeat after an update, [Part 8](../08-day2-operations/index.mdx)), then the two handover tasks. Every task has a script under `scripts/deploy/07-validation-handover`, a page here and a test.

## Tasks

| Task | What it does | Script folder | Azure CLI script |
|------|--------------|---------------|------------------|
| [Task 01: Cluster Health](./task-01-cluster-health-validation.mdx) | Cluster service, nodes, Storage Spaces Direct, networks, quorum, Arc agent | `scripts/deploy/07-validation-handover/task-01-cluster-health-validation` | no |
| [Task 02: Arc Connectivity](./task-02-arc-connectivity-validation.mdx) | From each node: the Arc agent, its extensions and the Arc endpoints | `scripts/deploy/07-validation-handover/task-02-arc-connectivity-validation` | no (the Azure side is [Phase 04, Task 04](../04-cluster-deployment/phase-04-arc-registration/index.mdx)) |
| [Task 03: Network Configuration](./task-03-network-configuration-validation.mdx) | Adapters, virtual switches, Network ATC intents, RDMA, cluster networks, DNS, endpoints | `scripts/deploy/07-validation-handover/task-03-network-configuration-validation` | no |
| [Task 04: Storage Performance](./task-04-storage-performance-validation.mdx) | Pools, virtual disks, physical disks, volumes, and an optional I/O latency test | `scripts/deploy/07-validation-handover/task-04-storage-performance-validation` | no |
| [Task 05: Deployment Documentation](./task-05-deployment-documentation.mdx) | Writes the documentation package of the instance | `scripts/deploy/07-validation-handover/task-05-deployment-documentation` | no |
| [Task 06: Customer Transfer](./task-06-customer-transfer.mdx) | Gives the customer administrator access to the Azure resources and writes the transfer record | `scripts/deploy/07-validation-handover/task-06-customer-transfer` | yes |

## How the scripts behave

- Each reads `infrastructure.yml` (`-InfrastructureFile`, required) and nothing else; `cluster.name` is the cluster, `azure.location` the region where an endpoint list is needed.
- None asks a question. They connect as the account that runs them, or as `-Credential` where that is offered.
- Exit codes: `0` nothing failed (warnings are listed), `1` a check failed or the cluster could not be read, `2` a value in the file is missing or not usable (nothing is sent).

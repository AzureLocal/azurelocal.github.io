# Task 01: Validate SDN Prerequisites

[![Runbook](https://img.shields.io/badge/Type-Runbook-blue?style=flat-square)](./index.mdx)
[![Azure](https://img.shields.io/badge/Platform-Azure_Local-0078D4?style=flat-square&logo=microsoftazure)](https://learn.microsoft.com/en-us/azure/azure-local/)

> **DOCUMENT CATEGORY**: Runbook   
> **SCOPE**: SDN prerequisite validation   
> **PURPOSE**: Verify cluster meets SDN requirements   
> **MASTER REFERENCE**: [Microsoft Learn - SDN Overview](https://learn.microsoft.com/en-us/azure/azure-local/concepts/sdn-overview?view=azloc-2611)

**Status**: Active

## Overview

Before enabling SDN on Azure Local, you must verify that your cluster meets all prerequisites including version requirements, network intent configuration, and workload compatibility.

## Prerequisites Checklist

### Version Requirements

| Requirement | Minimum Version |
|-------------|-----------------|
| Azure Local | 2506 |
| OS Build | 26100.xxxx or later |
| Arc Agent | Latest |

Learn: SDN enabled by Arc is available with Azure Local 2506 with OS version 26100.xxxx or later ([SDN overview](https://learn.microsoft.com/en-us/azure/azure-local/concepts/sdn-overview?view=azloc-2611)). The current release, 12.2611.1004.9 (OS 26100.33822), meets both.

### Network Intent Compatibility

SDN enabled by Arc only supports specific Network ATC configurations. Verify your intent matches one of these patterns:

| Pattern | Description | Storage Connectivity |
|---------|-------------|---------------------|
| Group All Traffic | Single intent for all traffic | Switched only |
| Management + Compute with Separate Storage | 2 intents | Switched or Switchless (≤4 nodes) |
| Fully Disaggregated | Up to 3 separate intents | Switched or Switchless (≤4 nodes) |

### Workload Compatibility

| Workload | SDN Compatible |
|----------|----------------|
| Azure Local VMs (deployed from Azure) | ✅ Yes |
| Hyper-V VMs (deployed locally) | ❌ No - Use on-premises SDN |
| AKS on Azure Local | ✅ Yes, with one limit: an NSG on the logical network that AKS workloads use, or on an AKS workload VM NIC, is not supported |
| Multi-cast applications | ❌ No |

## Execution Options

<Tabs groupId="deployment-method">
<TabItem value="manual" label="Azure Portal" default>

### Steps

1. Navigate to **Azure Portal** → **Azure Arc** → **Azure Local**
2. Select your cluster resource
3. Go to **Overview** and verify:
 - **Version**: 2506 or later
 - **Connection Status**: Connected

:::warning Portal Limitation
Network ATC intent configuration and OS build version are **not visible in the Azure Portal**. You must use PowerShell (Direct Script or Orchestrated Script) to validate these prerequisites. The portal can only confirm cluster version and Arc connectivity.
:::

### Verification (Portal Only)

Document the following from the portal:
- [ ] Cluster version is 2506+
- [ ] Arc connection is active

**For full validation**, use the Direct Script or Orchestrated Script tab to also verify:
- OS build (26100.xxxx+)
- Network intent compatibility
- AKS check: no NSG on the AKS logical network or on AKS workload VM NICs

</TabItem>

<TabItem value="orchestrated" label="Orchestrated Script">

### PowerShell

> **When to use**: Check the prerequisites from a management host before you enable SDN. `Invoke-SdnPrerequisites-Orchestrated.ps1` is read only: it asks one node over PowerShell remoting and changes nothing. The earlier `Test-SdnPrerequisites.ps1` is removed.

#### Script

| Script | What it does |
|---|---|
| `scripts/deploy/05-operational-foundations/phase-01-sdn-deployment/task-01-validate-sdn-prerequisites/powershell/Invoke-SdnPrerequisites-Orchestrated.ps1` | Checks, from Microsoft Learn: the OS build is 26100 or later; the Azure Local version is 2506 or later (a version it cannot read is a warning); the instance is registered and Connected; the network intents of the file (`networking.intents[]`) and of the machine (`Get-NetIntent`) are a layout that SDN enabled by Arc supports; whether SDN by Arc is already on (reported, not a failure); a sign of SDN managed by on-premises tools (a warning, because the script cannot prove it); and AKS (information: AKS is supported, an NSG on the AKS logical network or its VM NICs is not). Supports `-WhatIf` (lists the checks and runs none). |
| `scripts/deploy/04-cluster-deployment/phase-06-post-deployment/task-01-deploy-sdn/powershell/Enable-ArcSdn.ps1` | Turns on SDN enabled by Azure Arc when `sdn.enabled` of `infrastructure.yml` is true. Under `-WhatIf` it checks the OS build, the DNS record and the intent layout, and changes nothing. It uses the same intent rules (`scripts/common/sdn/AzlSdn.psm1`). See [Deploy SDN](../../04-cluster-deployment/phase-06-post-deployment/task-01-deploy-sdn.mdx). |

Parameters of the check: `-InfrastructureFile` (required), `-ComputerName` (default: the first node of `nodes[]` that answers), `-Credential` and `-LogPath`. The login is `-Credential`, else the LCM user (`identity.active_directory.lcm_user`) with Active Directory or the local administrator (`identity.local_admin`) with local identity; the password is a secret reference. The script never prompts. Exit 0: every check passed (warnings and information allowed) or the checks were listed under `-WhatIf`. Exit 1: a check failed or no node answered. Exit 2: a value in the file is missing or there is no login; nothing was checked.

#### Run

```powershell
./Invoke-SdnPrerequisites-Orchestrated.ps1 -InfrastructureFile ./infrastructure.yml -WhatIf
./Invoke-SdnPrerequisites-Orchestrated.ps1 -InfrastructureFile ./infrastructure.yml

# Then the plan of the enablement
./Enable-ArcSdn.ps1 -InfrastructureFile ./infrastructure.yml -WhatIf
```

## Validation Checklist

Complete this checklist before proceeding to SDN enablement:

| Requirement | Status | Notes |
|-------------|--------|-------|
| Azure Local version 2506+ | ☐ | |
| OS build 26100.xxxx+ | ☐ | |
| Arc connection active | ☐ | |
| Network intent compatible | ☐ | Document pattern used |
| No NSG on the AKS logical network or on AKS workload VM NICs | ☐ | AKS itself is supported |
| No existing on-premises SDN | ☐ | |

## Troubleshooting

| Issue | Resolution |
|-------|------------|
| Version too old | Update Azure Local to 2506 or later |
| Arc not connected | Run `Sync-AzureStackHCI` and verify connectivity |
| Incompatible network intent | Reconfigure Network ATC before enabling SDN |
| AKS workloads present | SDN enabled by Arc supports AKS. Do not associate an NSG with the logical network used for AKS workload deployment or with AKS workload VM NICs |
| Existing SDN via WAC/SDN Express | Cannot migrate - choose one method |

**Status**: Active

## Overview

Backups protect data and allow point-in-time recovery, but restoring can take hours. Continuous replication keeps an up-to-date copy at a second location for rapid failover and minimal data loss.

Azure Local supports two continuous replication technologies: Azure Site Recovery and Hyper-V Replica. Azure Backup is the Azure backup service. For on-premises backup, use a customer-selected backup solution that supports Azure Local.

## Decide: backup, replication or both

| Approach | Use it for | Considerations |
| --- | --- | --- |
| Backup | Point-in-time recovery and protection of VM data. Use host-level backup for full-VM recovery and guest-level backup for critical applications. | A restore can take hours. Keep offsite copies. |
| Azure Site Recovery | Continuous replication of Azure Local VMs to Azure. | RPO can be as low as 30 seconds. Failover to Azure can be planned or unplanned. |
| Hyper-V Replica | Asynchronous replication between two Azure Local clusters for on-premises disaster recovery. | Requires a second cluster. It is not configurable in the Azure portal. |
| Backup and replication | Use backup for point-in-time recovery and replication for rapid failover and minimal data loss. | These approaches address different recovery needs. |

## Prerequisites

| Requirement | Applies to |
| --- | --- |
| A Recovery Services vault | Azure Site Recovery |
| Connectivity to Azure on port 443 | Azure Site Recovery |
| A supported backup solution that supports Azure Local | Backups |
| A second Azure Local cluster | Hyper-V Replica |

For backup tools, see [Virtual machine resiliency for Azure Local](https://learn.microsoft.com/en-us/azure/azure-local/manage/disaster-recovery-vm-resiliency), in the **Backup Tools** section. Check the solution's support statement and keep offsite copies.

## Step 1.1 Choose the backup approach

Choose host-level backup, guest-level backup, or both based on your recovery needs.

| Approach | How it works | Recovery use |
| --- | --- | --- |
| Host-level | An agent runs on the cluster nodes. It protects whole VMs, is operating-system agnostic, and does not require an agent in each guest. | Full-VM recovery |
| Guest-level | An agent runs inside each VM. It is application-aware and supports item-level recovery for databases and similar applications. | Critical applications and item-level recovery |

Use host-level backup for full-VM recovery and guest-level backup for critical applications. Select an on-premises backup solution that supports Azure Local, and check its support statement. Azure Backup is the Azure backup service. Configure the selected solution according to its supported guidance.

## Step 1.2 Configure Azure Site Recovery replication

Azure Site Recovery replicates Azure Local VMs to Azure. Its RPO can be as low as 30 seconds.

In the Azure portal, start disaster recovery and prepare the infrastructure from the Azure Local resource. Then continue from the Recovery Services vault:

1. Select **Replicate**, then **Hyper-V machines to Azure**.
2. Set the source Hyper-V site, target subscription, post-failover resource group, and Resource Manager deployment model.
3. Select managed disk storage, which is recommended.
4. Select a virtual network and subnet for the failover VMs. You can set these later.
5. Configure replication, then use the available recovery operations as needed:
   - Test failover uses an isolated network and is non-disruptive.
   - Fail over to Azure, either planned or unplanned. In-memory state is lost.
   - Re-protect after failover.
   - Perform a planned failback, then reverse replication.

The Azure Site Recovery extension for Azure Local deploys automatically to all nodes, but it is in preview and only for test environments. For production, configure manually by using the Hyper-V to Azure disaster recovery option.

Azure Site Recovery is not supported for Trusted launch VMs.

## Step 1.3 Configure Hyper-V Replica (optional)

Hyper-V Replica is built-in, asynchronous replication between two Azure Local clusters for on-premises disaster recovery. It is not configurable in the Azure portal. Use PowerShell on the nodes or Failover Cluster Manager from a Windows Server machine.

1. Enable both clusters as replica servers.
2. Set authentication: use Kerberos in a domain, or certificates otherwise.
3. Open firewall rules for replication traffic.
4. Enable replication for each VM. Configure the replica server or cluster, virtual hard disks, replication frequency of 30 seconds, 5 minutes, or 15 minutes, and the number of recovery points.
5. Use test failover, failover, reverse replication, and failback as needed.

## Step 1.4 Validate

Check that:

- A test failover completes.
- A restore test of one VM succeeds.
- Recovery points exist.

## Trusted launch notes

If you restore a Trusted launch VM to a different Azure Local instance, it can no longer be managed through Azure Arc. Manage it with local tools instead.

Automatic key backup is in preview. When creating the instance, provide a backup Azure Key Vault to back up system-level secrets, including Trusted launch VM keys and BitLocker recovery keys.

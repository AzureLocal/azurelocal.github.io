Task 03: Configure Enhanced Telemetry

DOCUMENT CATEGORY: Runbook SCOPE: Configure diagnostic level, streaming data client, and EU location settings f... PURPOSE: Configure diagnostic level, streaming data client, and EU location settings for Azure Local telemetry MASTER REFERENCE: Azure Local Telemetry and Diagnostics

Status: Active

Enhanced telemetry settings enable comprehensive diagnostics, proactive support, and real-time monitoring for Azure Local clusters.

Overview​

Telemetry configuration includes three key settings:

  • diagnosticLevel: Controls the amount of diagnostic data the instance sends to Microsoft. The values are Off, Basic and Enhanced (Learn: DiagnosticLevel)
  • streamingDataClient: Enables streaming of telemetry data. A deployment setting
  • euLocation: Keeps diagnostic data in the EU. A deployment setting

The diagnostic level is the only one of the three that Learn documents as a setting you can change after the deployment (the desired property diagnosticLevel of the instance, Learn: DesiredPropertyDiagnosticLevel). streamingDataClient, euLocation and episodicDataUpload are parameters of the deployment (Learn: ARM template parameters reference); Learn documents no way to change them afterwards.

Prerequisites​

  • Azure Local cluster registered with Azure Arc
  • Owner or Contributor role on the cluster resource
  • Understanding of data privacy requirements
  • Knowledge of data residency requirements (EU vs non-EU)

Values from infrastructure.yml​

The values for this task come from infrastructure.yml (schema 5). Every key, with its type, default and example, is in the variables reference.

Execution Options​

  • Azure Portal
  • Orchestrated Script
  • Azure CLI

Steps​

  1. Navigate to the Azure portal → Azure Arc → Azure Local
  2. Select your cluster resource
  3. Go to Settings → Configuration
  4. Locate the Diagnostics section
  5. Configure the following settings:
  • Diagnostic Level: Select Off, Basic or Enhanced
  1. Click Save

The streaming data and EU location settings are set when the cluster is deployed (the portal and the ARM template ask for them there). infrastructure.yml carries them as security.telemetry.streaming_data, episodic_data_upload and eu_location.

Diagnostic Levels​

LevelData Sent (Learn: DiagnosticLevel)
OffNo diagnostic data is emitted
BasicBasic diagnostic data, including essential health metrics
EnhancedEnhanced diagnostic data, including detailed performance and usage metrics

There is no Full level.

PowerShell​

When to use: Set the diagnostic level of the instance from security.telemetry.diagnostic_level of infrastructure.yml, from a management host. The script is idempotent. The earlier Set-TelemetryConfiguration.ps1 is removed: Microsoft Learn documents no supported way to do what it did.

Script​

ScriptWhat it does
scripts/deploy/05-operational-foundations/phase-05-licensing-telemetry/task-03-configure-enhanced-telemetry/powershell/Invoke-TelemetryConfiguration-Orchestrated.ps1Reads the instance (Get-AzStackHciCluster). When its desired diagnostic level is the one of the file, nothing is changed. Otherwise it runs Update-AzStackHciCluster -DesiredPropertyDiagnosticLevel <level>, reads the instance again and runs Sync-AzureStackHCI on one node, so the machines take the setting now and not at their next daily sync (-SkipSync leaves that out). It also shows the diagnostic data settings of the deployment (streaming data, episodic data upload, EU location), which it cannot change. Supports -WhatIf (reads Azure, changes nothing, no sync).

Parameters: -InfrastructureFile (required), -ComputerName (the node for the sync; default: the first node of nodes[]), -Credential, -SkipSync and -LogPath. With security.telemetry.diagnostic_level absent the script does nothing and exits 0; it refuses scenario.connectivity disconnected (exit 2). It does not sign in: run Connect-AzAccount -Tenant <azure.tenant_id> first, with Contributor or Owner on the instance. The login for the sync is -Credential, else the account the file names (the LCM user with Active Directory, the local administrator with local identity; the password is a secret reference). A sync that fails is a warning, not a failure: the machines sync on their own. Exit 0: the level is as the file says (set now, already so, planned, or not asked for). Exit 1: an Azure call or a precondition failed. Exit 2: a value in the file is missing or not usable.

Run​

Connect-AzAccount -Tenant <azure.tenant_id>

./Invoke-TelemetryConfiguration-Orchestrated.ps1 -InfrastructureFile ./infrastructure.yml -WhatIf
./Invoke-TelemetryConfiguration-Orchestrated.ps1 -InfrastructureFile ./infrastructure.yml

Azure CLI​

When to use: Run the task from a host that has the Azure CLI and not the Az PowerShell modules. The script is PowerShell 7 that calls az; it reads infrastructure.yml and carries no values of its own.

Script​

ScriptWhat it does
scripts/deploy/05-operational-foundations/phase-05-licensing-telemetry/task-03-configure-enhanced-telemetry/azurecli/Invoke-TelemetryConfiguration-Orchestrated.azcli.ps1The Azure CLI twin: reads the instance (az stack-hci cluster show) and, when the desired level differs from the file, runs az stack-hci cluster update --desired-properties diagnostic-level=<level>. Azure side only: it does not run the sync on a node, so the machines take the setting at their next daily sync. Supports -WhatIf.

Requires: PowerShell 7 and the Azure CLI, signed in with az login --tenant <azure.tenant_id>, with Contributor or Owner on the instance. Needs the Azure CLI extension stack-hci (az extension add --name stack-hci); the script does not install it.

Run​

./Invoke-TelemetryConfiguration-Orchestrated.azcli.ps1 -InfrastructureFile ./infrastructure.yml -WhatIf

./Invoke-TelemetryConfiguration-Orchestrated.azcli.ps1 -InfrastructureFile ./infrastructure.yml

Diagnostic Level Details​

Off​

  • No diagnostic data is emitted

Basic​

  • Basic diagnostic data, including essential health metrics

Enhanced​

  • Enhanced diagnostic data, including detailed performance and usage metrics

Source: Learn: DiagnosticLevel. There is no Full level, and Learn does not say which individual data items each level carries, so this page does not list any.

EU Data Boundary​

Whether diagnostic data stays in the EU is the euLocation setting of the deployment: "Specifies whether to send and store telemetry and diagnostic data within the European Union (EU)" (Learn: ARM template parameters reference). In infrastructure.yml it is security.telemetry.eu_location. Learn documents no command that changes it after the deployment, so plan it before you deploy: this task does not change it.

Verification​

# The desired and the reported diagnostic level of the instance
Get-AzStackHciCluster -ResourceGroupName <azure.resource_group> -Name <cluster.name> |
 Select-Object DesiredPropertyDiagnosticLevel, ReportedPropertyDiagnosticLevel

# Check telemetry connectivity (from a node)
Test-NetConnection -ComputerName "dc.services.visualstudio.com" -Port 443

Troubleshooting​

IssueResolution
Telemetry not sendingVerify firewall allows HTTPS to telemetry endpoints
Reported level differs from the desired levelThe machines take the setting at the next sync: run Sync-AzureStackHCI on a node, or wait for the daily sync
Streaming data or EU location differ from the planThey are deployment settings; Learn documents no way to change them afterwards
Diagnostic level resetRun the script again

Telemetry Endpoints​

Ensure firewall allows outbound HTTPS (443) to:

  • dc.services.visualstudio.com
  • *.applicationinsights.azure.com
  • *.monitor.azure.com
  • *.blob.core.windows.net

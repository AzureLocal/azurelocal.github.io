## Overview

PowerShell provides the orchestration layer for much of the Azure Local automation estate. It is used to load variables, execute helper-driven workflows, run platform-specific deployment tasks, and bridge stages where Infrastructure as Code tools cannot fully automate the outcome.

## Where PowerShell Fits

| Area | Typical Use |
|---|---|
| Variable loading | Read and validate `infrastructure.yml` |
| Script orchestration | Chain multi-step deployment tasks |
| Azure automation | Execute `Az` module workflows and helper functions |
| On-premises execution | Configure nodes, trigger validations, and perform operational tasks |
| Wrapper scripts | Drive Terraform, Ansible, and external tooling consistently |

## Common Script Patterns

| Pattern | Purpose |
|---|---|
| **Direct Script** | Run directly on the target node or management host |
| **Orchestrated Script** | Execute from a management server across multiple systems |
| **Azure CLI Variant** | PowerShell wrapper around `az` commands where needed |

## Variable Loading

PowerShell automation starts by loading the shared configuration, the master `infrastructure.yml`:

```powershell
Import-Module ./scripts/common/infrastructure/AzlInfrastructure.psm1
$infra = Import-AzlInfrastructure -Path ./infrastructure.yml   # stops if the file has errors
```

The script resolves environment-specific values from the central source of truth instead of hard-coding them inline. A test fails the build when a script carries a value that a deployment chooses. A script parameter that is not registered in the master registry fails a test too.

## Helper Usage

Common helpers cover:

- Loading and validating the infrastructure file (`AzlInfrastructure.psm1`)
- Variable lookups by path (`Get-AzlInfrastructureValue`)
- Resolving secret references: `keyvault://`, `env://`, `file://` and `command://` (`AzlSecret.psm1`)
- Writing the Terraform and Ansible variable files (`config/variables/scripts/New-IacVariableFiles.ps1`)
- Progress lines with an optional `-LogPath` file, and preflight validation

## Execution Guidance

Use PowerShell when you need:

- Strong operational control over sequence and retries
- Local execution on Windows-based management systems
- Deep integration with Azure PowerShell modules
- A wrapper layer around Terraform, Ansible, or Azure CLI tasks

For the execution model used by the main delivery runbook, also see [How to Use This Runbook](../../implementation/02-how-to-use-this-runbook.mdx).

## Entry Points for the Azure Local Deployment Flow

These scripts take the master `infrastructure.yml` and run unchanged on a workstation or in a pipeline (PowerShell 7):

| Script | Phase | Guide |
|---|---|---|
| `scripts/deploy/04-cluster-deployment/phase-03-os-configuration/Invoke-AzureLocalOsConfiguration.ps1` | OS configuration of every node: plan, apply, verify, one report | [Automated OS configuration](../../implementation/04-cluster-deployment/phase-03-os-configuration/automated-os-configuration.mdx) |
| `scripts/deploy/04-cluster-deployment/phase-05-cluster-deployment/Invoke-AzureLocalArmDeployment.ps1` | Preconditions, ARM Validate, approval, ARM Deploy | [ARM Validate and Deploy](./arm-validate-deploy.mdx) |

## Repository Areas

| Path | Purpose |
|---|---|
| `scripts/common/` | Shared helpers and reusable utilities |
| `scripts/deploy/` | Deployment phase scripts. The generated [script status](https://github.com/AzureLocal/azurelocal-toolkit/blob/main/docs/script-status.md) page says which task has a real script |
| `scripts/validation/` | Validation and post-deployment checks |
| `config/variables/` | Shared configuration consumed by the scripts |

## Example Exports

```powershell
./config/variables/scripts/New-IacVariableFiles.ps1 -InfrastructureFile ./infrastructure.yml -OutputDirectory D:\work\iac
```

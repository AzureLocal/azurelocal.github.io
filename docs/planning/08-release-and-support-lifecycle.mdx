## Current release

The latest release of Azure Local is **12.2611** (November 2026). New deployments use build **12.2611.1004.9** by default, available since 20 November 2026, with OS build **26100.33822**. In the 2611 release all new and existing deployments run OS version 26100.33822 (download it from the Azure portal), so drivers must be compatible with that OS version or with Windows Server 2025. For Integrated System or Premier solution hardware the OS is preinstalled; work with your OEM for a compatible OS image and driver. Sources: [Release information](https://learn.microsoft.com/en-us/azure/azure-local/release-information-23h2?view=azloc-2611) and [What's new in 2611](https://learn.microsoft.com/en-us/azure/azure-local/whats-new?view=azloc-2611#features-and-improvements-in-2611).

Microsoft says the 2611 release "includes various reliability improvements and bug fixes". It ships .NET 8.0.34 and 10.0.15, PowerShell 7.6.10, and the November OS security update ([KB5131080](https://learn.microsoft.com/en-us/azure/azure-local/security-update/security-update?view=azloc-2611), OS build 26100.33822, released 10 November 2026). The same OS build also ships to 2610 as the November security update **12.2610.1004.55** (20 November 2026).

:::note Build numbers
Solution versions are written `12.<YYMM>.<build>`. This site says "2611" or "12.2611" for the release train. Microsoft publishes the exact build number and OS build for each train on the release information page.
:::

:::info Pages audited against 2610
Most runbook pages were audited against Microsoft Learn view `azloc-2610` in November 2026 and say "Learn 2610" where they quote Learn. Those statements are the record of that audit, not a claim that the page only applies to 2610. Their Learn links now open view `azloc-2611`. The 2611 release notes change no deployment step on this site; the validation changes that affect your build are in [What changed in 2611](#what-changed-in-2611).
:::

## Release model

Azure Local moved from one annual release to a monthly release train. Each train is one of the following:

| Build type | What it contains |
|------------|------------------|
| **Feature build** | The first build in a train. Adds product enhancements, including updates to Azure Local services and agents. |
| **Cumulative build** | Incremental updates on top of the most recent feature build. |
| **Security build** | Released the same week as Patch Tuesday, so you can address vulnerabilities without waiting for a cumulative or feature release. Starting with 2604, security updates are available before the cumulative update. On a system already on the latest release a security update is security-only; on an applicable older release it also applies the Azure Local updates needed to reach the target security release. Security updates follow the supported update paths. |

Microsoft Learn's 2611 release information calls the third build type a **security build**; earlier views called it a quality build (optional, security-only, not cumulative). [About updates](https://learn.microsoft.com/en-us/azure/azure-local/update/about-updates-23h2?view=azloc-2611#lifecycle-cadence) lists cumulative and security updates as monthly and feature updates as semiannual.

Key points that affect planning:

- Starting with 2504, there are two solution versions each month. Version **11.25xx** stays on OS build 25398 (23H2). Version **12.25xx or 12.26xx** runs OS build 26100 (24H2). Each version keeps its OS build for all later updates.
- Before you install a feature update, install the last cumulative update. For example, install 2509 before you install 2510.
- Feature releases reach clusters that use a Solution Builder Extension (SBE) after your hardware vendor validates them. This typically takes a few weeks and varies by vendor. See [Update management and Solution Builder Extension](../operations/update-management-and-sbe.mdx).
- The Azure Arc resource bridge requires solution updates to be applied within one year, to keep certificates valid and Azure Local VM management working.

## Supported builds

To stay supported, install updates within the **N-6 released build window**, where N is the latest released build. With 2611 as N, 2605 is six releases behind (N-6) and is the oldest supported build. A solution outside that window is no longer supported, and Microsoft Support can only help you update it to a supported version, even during an outage. Planning an update or being in the middle of one does not make the solution supported. (The release information for views 2609 and earlier gave the window as six months.) Source: [Release information, key considerations](https://learn.microsoft.com/en-us/azure/azure-local/release-information-23h2?view=azloc-2611#key-considerations).

|------------------|--------------|----------|

| 12.2610.1004.50 (supersedes 12.2610.1004.41 of 2026-10-22) | 2026-11-02 | 26100.33650 |
| 12.2609.1003.7 | 2026-09-11 | 26100.33438 |

Microsoft Learn lists 12.2605 through 12.2611 as the supported versions in the release information summary. 12.2604 (12.2604.1003.1006, 2026-05-28, OS build 26100.32690) and everything older (12.2603 and earlier, and all 11.x and 10.x builds) are listed there as older versions. Dates are as published by Microsoft (some trains show a later availability date for a superseding build).

:::warning Azure Stack HCI 23H2 is out of support
The Azure Stack HCI, version 23H2 operating system (OS build 25398) reached end of support in April 2026. October 2025 (11.2510) was the final 23H2 release. Systems still on 25398 receive no monthly security or quality updates, and support requests are limited to patching to a supported release. Move them to the 12.x train.
:::

## Naming

Azure Stack HCI was renamed Azure Local. Some portal wizards, PowerShell cmdlet names (for example `Invoke-AzStackHciArcInitialization`), built-in role names (for example `Azure Stack HCI Administrator`), and OS strings still use the older name. Treat them as the same product.

## What changed in 2611

2611 (12.2611.1004.9) brings reliability improvements and bug fixes. Its [Features and improvements](https://learn.microsoft.com/en-us/azure/azure-local/whats-new?view=azloc-2611#features-and-improvements-in-2611) list one new capability, and its [fixed issues](https://learn.microsoft.com/en-us/azure/azure-local/known-issues?view=azloc-2611#fixed-issues) change some deployment validation results. The items that matter for the runbooks on this site:

| Area | Change in 2611 | What it means here |
|------|----------------|--------------------|
| OS and runtimes | OS build 26100.33822 for new and existing deployments; .NET 8.0.34 and 10.0.15; PowerShell 7.6.10 | Use 2611 media or update after registration; drivers must be compatible with 26100.33822 or Windows Server 2025 |
| GPU management (preview) | The portal GPU management experience no longer needs the Edge machine creation script. Starting with 2611, edge machine resources are created automatically ([Manage GPU fabric resources](https://learn.microsoft.com/en-us/azure/azure-local/manage/gpu-manage-fabric-resources?view=azloc-2611#prerequisites)) | Skip the script on 2611; on earlier releases it is still required. GPU management still needs solution version 12.2604.1003.x or later |
| Network validation | Inconsistent adapter link speeds across nodes are now a **critical error** (they were a warning that let an unsupported configuration deploy). Overlapping management and storage IP prefixes are now detected | Match link speeds per intent on every node and keep the management and storage subnets apart, or the 2611 validation stops the deployment |
| DNS validation | Cluster name object (CNO) IP-mapping and cluster DNS posture checks now report actionable conditions as **warnings** instead of informational messages | Read the warnings before you deploy; see [DNS records](../implementation/03-onprem-readiness/phase-01-active-directory/task-03-dns-node-a-records.mdx) |
| Deployment fixes | Fixed: multi-node installs failing when `Add-CauClusterRole` cannot add the Cluster-Aware Updating role; storage cluster creation failing when the Active Directory computer object is not found during `New-Cluster` | No runbook change |
| Update fixes | Fixed: zero-downtime updates blocked by a download-tool dependency; downloads failing when the PowerShell execution policy blocks the download connector or BITS is stopped or its helper configuration is missing; a `0x50` SMB bug check during updates; MPIO registrations that might not be preserved during OS composition. Security updates can now be selected as update baselines. Pre-update Network Controller health issues are reported as warnings | See [Update management and SBE](../operations/update-management-and-sbe.mdx) |
| Security fix | .NET and PowerShell components updated for CVE-2026-111497 | Covered by the solution update |
| Azure Government | Arc resource bridge deployment in Azure Government now authenticates against the Azure Government endpoint | No runbook change |

Microsoft lists no known issues specific to 2611. The known issues carried over from earlier releases still apply, including the leftover .NET runtime files after a .NET update (first listed for 2610), Arc registration error 42, and the attack surface reduction rule that blocks the solution update. Check [Known issues for 2611](https://learn.microsoft.com/en-us/azure/azure-local/known-issues?view=azloc-2611) before each deployment and maintenance window.

## Planning guidance

1. Target the latest train (12.2611) for new deployments. Hardware that ships with an older preinstalled OS can be updated after Azure Arc registration. On clusters that use a Solution Builder Extension, the 2611 release reaches you after your hardware vendor validates it.
2. Budget a recurring update window. A cluster outside the N-6 released build window (older than 2605 while 2611 is the latest) is unsupported.
3. Confirm with your hardware vendor which Solution Builder Extension version matches the release you plan to run.
4. Re-check [known issues](https://learn.microsoft.com/en-us/azure/azure-local/known-issues?view=azloc-2611) before each maintenance window.
5. If the `AzureEdgeAlerts` extension is installed, update it to version 12.2607.5.0 or later before you update to 2610 (Microsoft Learn release information).

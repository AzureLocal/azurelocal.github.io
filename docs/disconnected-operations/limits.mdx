# Limits and known issues

## Documented limitations

| Area | Limitation |
|------|------------|
| Access | Access requires approval. If a subscription is not approved, create actions in the acquire flow fail. |
| Services | Only the services in the [supported services list](./index.mdx#what-the-local-control-plane-supports) are available in the local control plane. |
| Control plane versions | Azure Local can never be on a newer version than the disconnected operations build. |
| Management cluster | Must be dedicated. Production needs three nodes. Do not run other workloads on it. |
| Certificates | Self-signed certificates are not supported. A fully disconnected site cannot use a public CA, because deployment fails without internet access for CRL and OCSP. |
| Container network | The built-in container network range cannot be reconfigured. Isolate 10.131.19.0/24 if you use it. |
| Identity | Only Active Directory and AD FS are validated. Only Universal groups are supported. There is no force synchronization, the initial sync can take up to six hours, and users and groups removed after the last sync are not cleaned up. There are no management groups or aggregate root level. |
| Azure Local VMs | VM images can only be created from a local share (not Marketplace, an Azure storage account or an existing Azure Local VM). Network interfaces are created with the Azure CLI, not the portal. Proxy servers are not supported for outbound connections. Trusted launch can only be created with the Azure CLI, and boot integrity verification is not supported. |
| Azure Resource Manager | Template specs are not supported; deployments that use them fail. |
| Unsupported scenarios | Non-Azure Local VMs and non-AKS Kubernetes clusters. If you test them, they must trust your custom CA and you pass `-custom-ca-cert` when Arc-enabling them. |
| Scale | Running more than 20 workload clusters can affect control plane stability. Learn says to stay at 20 or fewer until the supported range is expanded. |
| Memory | The appliance uses 78 GB of memory. On nodes with less than 128 GB, Learn describes reducing the appliance VM to 64 GB after deployment and before you deploy Azure Local instances. |
| Passwords | Special characters such as single or double quotes in the management TLS certificate password, external certificate passwords or observability secrets can make appliance deployment fail. |
| Support | No remote support, portal-based log collection, or metrics and telemetry streaming in disconnected mode. |
| Air-gapped data movement | Updates and support logs cross the boundary by your own process. |

## Known issues

Microsoft updates the known issues article continuously with critical issues and required workarounds, organized by release. Review it for your release before you plan a deployment and again before each update. It currently covers, among others:

- certificate generation, CRL and bootstrap failures,
- air-gapped update and signing certificate problems,
- host guardian certificates missing when you deploy more clusters after the management cluster,
- cloud deployment validation or deployment that gets stuck or falls out of sync with the portal,
- Azure Key Vault permission propagation during cluster deployment,
- portal, Azure CLI, subscription and Azure Local VM issues,
- AKS issues, including AKS deployments in fully air-gapped scenarios.

Read the article for symptoms, causes and mitigations. This site does not copy them, because they are release specific and change often.

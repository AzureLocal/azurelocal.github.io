Requirements and Planning

Review these requirements before you request access. Everything here comes from Microsoft Learn; the sources list the articles.

Eligibility​

To procure disconnected operations you must meet all of these criteria:

CriterionDetail
Eligible agreementYou need an eligible agreement with Microsoft. The Microsoft online subscription program (MOSA) is not eligible.
Support planAn active support plan, Standard or higher, with Microsoft or through a partner.
Business needA valid need to operate disconnected, because of connectivity limits or regulatory restrictions.
Operational and technical readinessStaff, or a preferred partner, able to deploy and operate it, and the workloads and application requirements identified up front.
HardwarePremier Solutions for Azure Local. You bring your own hardware and deploy a dedicated management cluster.

To get access, work with your Microsoft account team. You or the account team complete the prequalification form and wait for approval. Learn says you are notified of the status (approved, rejected, queued or more information needed) within 10 business days.

The dedicated management cluster​

The local control plane runs on a separate Azure Local management cluster that is:

  • exclusively dedicated to control plane and management components,
  • isolated from application and tenant workload clusters,
  • sized to meet the hardware requirements of disconnected operations.

Production deployments require a dedicated three-node management cluster. Learn recommends a switchless storage network design for it. Do not deploy anything other than the control plane to the management cluster; deploy tenant workloads on separate Azure Local clusters.

Minimum production specification​

SpecificationDatacenter configurationStandard configuration
Minimum number of nodes33
Memory per node512 GB128 GB
Cores per node24 physical24 physical
Storage per node8 drives, minimum 2 TB each (SSD or NVMe)6 drives, minimum 2 TB each (SSD or NVMe)
Boot disk960 GB SSD or NVMe960 GB SSD or NVMe
Intended scaleLarge datacenter scale, 1000+ nodesMedium deployments, 100+ nodes

For boot disks smaller than 960 GB, the appliance is installed on extra data disks from the nodes, so make sure you have enough data drives. If you need a smaller management cluster, Learn says to contact your account team.

To find supported hardware, open the Azure Local catalog, select Disconnected operations under Solution capability, then check the Solution capability tab of a solution for the configurations that can be a management cluster.

Capacity planning​

  • Size hardware to the control plane requirements.
  • Do not use the management cluster as a general-purpose compute pool.
  • Keep capacity headroom for updates and lifecycle operations.
  • Plan for node repair and replacement so the management cluster stays operational after unexpected hardware events.

Proof of concept​

Learn recommends a four-node Azure Local hardware configuration for a proof of concept, and describes three ways to arrange it. If you already have workload clusters, procure a three-node dedicated management cluster instead.

OptionLayoutUse it to
Management-focusedThree-node management cluster plus a one-node workload clusterEvaluate the control plane architecture, sizing and isolation
Workload-focusedOne-node management cluster (testing only) plus a three-node workload cluster, or a one-node workload clusterTest workload placement, resiliency and application deployment
Multi-cluster-focusedOne-node management cluster (testing only) plus three separate one-node workload clustersManage several clusters from one control plane

Learn recommends the production hardware configuration even for a proof of concept, because it is supported and can later be used in production. If you diverge, the control plane nodes need at least 256 GB memory, 24 cores, 4 TB dedicated SSD or NVMe storage and a 960 GB SSD or NVMe boot drive.

Network​

Disconnected operations run on Azure Local, so the standard Azure Local network requirements apply first. The control plane is a virtual machine appliance with two virtual NICs on the network intent: a management vNIC and an ingress vNIC.

ItemRequirement
Management IP poolReserve a management IP address pool as part of the Azure Local network plan.
Ingress IPIn the same subnet as the Azure Local instance but outside the reserved range used for instance deployment. It needs DNS resolution to the appliance FQDN.
Management IPA valid, unused IP on the local network, reachable if you call the lower management APIs from outside the cluster.
Container networkThe appliance has a built-in container network range that you cannot reconfigure. If you already use 10.131.19.0/24, isolate it from the disconnected operations environment.
DNSAn explicit DNS zone for the appliance FQDN, not at the same level as your domain controller. DNS must resolve the ingress endpoints, including wildcard endpoints for backing services such as Key Vault and Container Registry.
External accessServices and clients outside Azure Local must resolve and route to the ingress IP on port 443.
Identity providerRoutable and reachable from the appliance on the management network intent.

If your ingress or management network needs a VLAN, Learn shows setting the default isolation ID on the management vNIC with Set-VMNetworkAdapterIsolation.

Identity​

You integrate with an existing identity solution. Learn lists the supported options and constraints:

  • Active Directory for groups and memberships, and Active Directory Federation Services (AD FS) for authentication. Only Active Directory and AD FS are validated for support.
  • Only Universal groups are supported for Active Directory.
  • You name a root operator at deployment. That user owns the operator subscription and adds other operators afterwards.
  • Role assignments and policies are not inherited from the operator subscription to other subscriptions. Each subscription has its own scope.

Collect these before deployment: the OIDC authority URI, the client ID of the AD FS application, a read-only LDAP account, the LDAP server and port (3268 or 3269 for the global catalog), the certificate chain information for the LDAP and OIDC endpoints, the root operator's UPN, and the GUID of the Active Directory group to synchronize from. An automation certificate is optional and supports fully automated deployments.

ShapeOne certificate per endpoint, with subject and SAN set. All certificates share one trust chain and are valid for at least two years from deployment.

Learn's OperationsModule includes helpers to create the certificate signing requests and issue the certificates from your CA. Learn also notes that certificate generation can hang in a Remote Desktop session that maps smart cards.

Security planning​

  • The appliance is a locked-down VM reachable only through the management NIC (limited commands for deployment and troubleshooting, secured with your certificate) and the ingress NIC (tenants and services, with your identity provider and RBAC).
  • Data in transit uses TLS 1.2 and 1.3, DTLS 1.2 and signed SMB. Secure boot, Microsoft Defender and Windows Defender Application Control are used on the appliance.
  • Data volumes are encrypted with BitLocker (AES-XTS 256-bit). See Operations for the recovery keys.
  • There is no built-in intrusion detection or prevention system. You deploy your own on the network path.
